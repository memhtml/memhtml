`@memhtml/index` is the SQLite layer under memhtml: the schema and its migrations, the indexer that projects the git tree into `index.db`, four-arm retrieval over that index, the state plane attached beside it as `state.db`, and the persistence half of the trace plane. It runs on Node's own `node:sqlite` and on `effect`, and it imports three workspace packages: `@memhtml/contracts` for paths, types, edge classes and errors, `@memhtml/domain` for the ranking math, and `@memhtml/html` for the memory file parser. Its manifest also lists `@memhtml/llm`, but no source file imports it, because an embedder reaches this package as a port typed by its shape. The CLI composes the database, indexer, retrieval and recorder services from this package, the MCP server and the CLI both call its `parseFacetFilters`, and the eval package runs the real indexer and retrieval over a generated corpus.

`makeDatabase` opens one connection for a scope and closes it when the scope ends. It turns on WAL mode, `synchronous = NORMAL` and foreign keys, waits up to five seconds for the write lock, and registers the SQL function `vector_distance_cos`, which calls `@memhtml/domain`'s `cosineDistance` rather than a second copy of that arithmetic. It then applies each pending `.sql` file in the migrations directory it is given (`MIGRATIONS_DIR` for the shipped schema) in filename order, each file in one transaction with its ledger row. Given a state path, it calls `attachState`, which attaches `state.db` under the schema name `STATE_SCHEMA` and runs `runStateMigrations` over the state migrations directory it is given (`STATE_MIGRATIONS_DIR` for the shipped one) against a separate ledger, so deleting `index.db` never marks a state migration as unapplied.

`DatabaseService` is the tag for the `DatabaseShape` that `makeDatabase` returns: `run`, `get` and `all` for one statement, `writeAll` for a list of `Write` values bound with `SqlValue` parameters, `script` for a whole SQL script, the two migration counts, and `hasState`. `writeAll` and `script` each run in one transaction, so one call commits whole or not at all. A call that meets `SQLITE_BUSY` is retried with jittered exponential backoff on a schedule capped at 20 seconds, and a failure reaches the caller as a `StorageFailure` that names only the operation, so SQL parameters and memory text stay out of the error.

The SQL lives in `migrations/` for `index.db` and in `state-migrations/` for `state.db`, and `schema-const.ts` names the identifiers both sides use. `files` holds one row per memory file. Its child tables for tags, entities, facets and citations cascade on update as well as on delete, because an archive move changes the primary key. `chunks` and `embeddings` key on the content hash, not on the path. CHECK constraints keep each relation in `edges` inside its class. The partial unique index `files_content_hash_active` refuses a second active, non-task row with the same content hash, so within one `index.db` the database itself enforces dedup. `FTS_INDEX_NAME` is `files_fts`, an external-content FTS5 table that triggers keep in step with `files`, over the one column `FTS_COLUMN`, so bm25 ranks one text and fusion does the weighting. `INDEX_STATE_ID` is the key of the one-row `index_state` table. `MEMORY_TABLES` lists, children first, the tables a rebuild empties, and a rebuild deletes rows from those tables only, so the trace tables in `TRACE_TABLES` and the state plane keep theirs. `STATE_TABLES` names `access` and `edge_corroboration`. `CHUNK_MAX_CHARS` (1,800), `SNIPPET_MAX_CHARS` (700) and `WRITE_BATCH_SIZE` (500 statements per transaction) are the size limits.

`IndexStateRow` is the schema of the `index_state` row: `head_sha`, the commit the index describes, then `embed_model` and `embed_dim`, the vector space as `<model-id>@<dim>` and as a number, then two timestamps. `readIndexState` selects the schema's own columns by name and decodes them. It returns `undefined` when there is no row and turns a malformed row into a `StorageFailure`. A row whose `head_sha` is NULL belongs to a rebuild that has not finished.

`GitPort` is the indexer's view of git, behind the `IndexGit` tag: `revParseHead`, `lsTreeR`, `catFileBatch`, `diffNameStatus`, `statusPorcelainV2`, `hashObject` and `readWorkingFile`, which return `TreeEntry`, `DiffEntry` and `StatusEntry` rows. It is declared here, so the indexer depends on a shape and not on `@memhtml/store`, and its tag differs from the store's `memhtml/Git` because the two shapes differ. `makeGitPort` builds the port from the store's git client, which `StoreGitShape`, `StoreTreeEntry`, `StoreChangedPath` and `StoreStatusEntry` describe, plus the file reader and failure builder in `GitAdapterDeps`. It fails on a HEAD with no commit, decodes blobs as UTF-8, and drops tree entries that are not blobs, such as submodules. It maps a copy to an add, never to a rename, because the source of a copy still exists. It drops ignored and unmerged status entries and keeps the source path of a staged rename, so the indexer can retire the old row in the same pass. Every rejection, a defect included, is logged with its git operation and returned as the caller's typed failure, so the returned failure carries none of git's own error output.

`makeIndexer` takes `IndexerDeps`, which are the database, the git port, the configured `embedWatermark` and `embedDim`, an optional `EmbedPort`, an optional `embedPersistEvery` slice size and a clock, and returns the `IndexerShape` behind the `Indexer` tag.

`rebuild` reads the tree at HEAD under `TREE_PREFIXES` with one `ls-tree` and one `cat-file --batch`, and keeps each path `isIndexablePath` accepts: a `.html` file under `projects`, `areas`, `resources` or `archive` whose name is not in `GENERATED_NAMES`. It changes the database only after those reads. In one transaction it clears `head_sha`, copies the vectors in the configured space to a temporary table, and empties the `MEMORY_TABLES`. It then projects every file, puts back each saved vector whose chunk id came back, and records the commit. A rebuild that stops after that transaction commits and before it records the commit leaves `head_sha` NULL, and `update` refuses that state with `IndexStale`. A file that fails to parse is listed as skipped in the `RebuildReport`, and the rest of the tree is still indexed.

`update` diffs the recorded commit against HEAD with `git diff --name-status -M` and then adds the uncommitted changes from `git status --porcelain=v2`. Committed changes apply first, so a path ends at its working-tree content. A rename that stays inside the indexed tree is an `UPDATE` of the row's path that the child tables' `ON UPDATE CASCADE` carries along, so a `git mv` keeps the file's chunks and vectors. When there is no `index_state` row at all, `update` runs a full rebuild instead. Its writes go in batches of `WRITE_BATCH_SIZE`, each its own transaction, and the recorded commit moves only after the last batch, so after a failed update the next one diffs from the same commit. `UpdateReport` counts the files added, modified, removed, renamed and dirty.

The stored vector space must equal `embedWatermark`. When it differs, `update`, `backfill`, `embedMissing` and any rebuild that cannot write vectors fail with `EmbedModelMismatch`. A `rebuild` with `embed: true` and an embedder bound is the one way past that check: it keeps only vectors already in the configured space, and it records that space before it writes any vector. A rebuild that cannot write vectors, over a store that holds some, fails with `RebuildNoEmbedRefused` unless `force` is set. `embedMissing` embeds the chunks that lack a vector in the configured space, either across all of `chunks` or only for the ids in `EmbedMissingOptions`, which is what `update` passes. It saves each slice, 960 chunks by default, before it embeds the next, so a model failure stops the pass, keeps what landed, and returns the count instead of failing. `backfill` runs the full scan, or only counts under `dryRun`, and returns a `BackfillReport` of what is left. `embedderBound` says whether an embedder is bound, and `vectorCoverage` reads the coverage ratio described below.

`projectFile` turns one parsed `MemoryDoc` into a `FileProjection`: the file's chunks and the `Write` list for its rows. It is pure, and `rebuild` and `update` both call it. It deletes the file's tags, entities, facets, citations and own authored edges, and only those of its chunks whose content hash is not the new one, so an edit to the head alone keeps the vectors. It then upserts the `files` row on `path` from `FILE_COLUMNS`, the one list behind the column list and the update clause. `archived` comes from the path, not from `memhtml-status`, because eviction is the move into `archive/`. Inbound edges are left alone, because each is another file's assertion.

`ftsTextFor` joins the title, gist and body with newlines into the FTS column. `disclosureTextFor` is the text recall may quote: the `<mark>` claim, the `<summary>` headlines, the facets as `name: value`, and the citations, collected from the whole article. No other text goes in, so ordinary paragraphs and the prose of a `<details>` body or an `<aside>` stay out, though a facet or citation inside one is still included. `entityRowsFor` adds a `concept:` row for each `<dfn>` and a `lang:` row for each `data-lang`, keeps `memhtml-entity` names as authored apart from trimming, and files an entity it cannot split into `type:name` under the type `unknown`. `authoredEdgesFor` turns head links into edge rows, strips the leading slash from each href, and drops a link to the file itself. `workspaceOf` is the directory under `projects/`, and `wordCountOf` counts whitespace-separated words.

`chunkText` splits an article's text into `Chunk` values of at most `CHUNK_MAX_CHARS` UTF-16 code units, with no overlap. An article that fits is one chunk, so its vector describes the whole article. A longer one packs whole sentences greedily and cuts a sentence that is too long, so no text is dropped. `chunkIdFor` is the sha256 of `<content hash>:<ordinal>`, so an identical body gets the same chunk ids at any path, and a `git mv` finds its vectors already stored.

`sanitizeFtsQuery`, `ftsQueryForms` and `hasFtsTerms` turn a caller's text into a MATCH string that FTS5 accepts. An apostrophe, a `type:name` reference, a hyphenated word or a bare `AND` each fails an FTS5 statement outright. So the sanitizer keeps only lowercased runs of Unicode letters and digits, keeps double-quoted spans as phrases when the query's quotes are balanced, and drops every other character instead of escaping it. `FtsQueryForms` holds `all`, the terms joined with `AND`, and `any`, the terms joined with `OR`, and `sanitizeFtsQuery` returns `any`. Both are empty when no term survives, and retrieval then drops the lexical arm, because an empty MATCH is an error too.

`RANK_ARMS` is the registry of `RankArm` entries that `buildRrfSql` folds into one statement. `fts` ranks `files_fts` by bm25, with weight 1.0. `vector` ranks each file by the cosine distance of its nearest chunk, with weight 1.0. `recency` ranks by `coalesce(event_at, updated_at)`, newest first, with weight 0.5. `salience` reads `state.access` and ranks by an exponential decay over the hours since the last access, or since `updated_at` for a file never accessed, plus the log of one plus the access count, plus any positive outcome score, with weight 0.4. Each arm returns `(path, rank)`, and the fold sums `weight / (rank + 60)` per path and breaks ties by path.

`activeArms` drops an arm whose input is missing, whether a query vector, the state plane or a query term, as the `RrfOptions` flags say. `PARAM_QUERY`, `PARAM_ARM_LIMIT`, `PARAM_FINAL_LIMIT` and `PARAM_QUERY_VECTOR` are the numbered slots `?1` to `?4`, so dropping the vector arm moves no other value. Salience leaves out tasks, `SALIENCE_EXCLUDED_TYPE`, and the person files under `SALIENCE_EXCLUDED_PREFIX`, `resources/people/`, and such a row keeps its ranks in the other arms when the scope admits it. `buildSnippetSql` fetches the chosen files' chunks, and `truncateSnippet` cuts one to `SNIPPET_MAX_CHARS`, ellipsis included.

`assembleScope` turns a `SearchScope` into an `AssembledScope`: one `ArmHoles` filter string that every arm receives, so a scope cannot reach three arms and miss the fourth, plus the values it binds from `?5` on. By default the filter keeps active rows and leaves out tasks, the type `EXCLUDED_BY_DEFAULT` names, and naming `task` in `memoryTypes` opts in. `workspace` must match exactly, `tags` widen the set to any listed tag, and `entity` is one `type:name` reference compared with ASCII case folded in SQL. `facets` are `FacetFilter` pairs that must all hold across names and widen within one name, which `facetConditions` builds as one `EXISTS` per name. `includeArchived` drops the archived filter, and `asOf` replaces it with a validity window at that instant, compared as strings. `parseFacetFilter` and `parseFacetFilters` read the `name=value` form, split it at the first `FACET_SEPARATOR`, and drop a spec with an empty side.

`makeRetrieval` takes `RetrievalDeps`, which are the database, an optional `QueryEmbedPort`, the configured watermark and a coverage floor, and returns the `RetrievalShape` behind the `Retrieval` tag. `search` takes a `SearchInput` and reads vector coverage first. When coverage is below the floor, no embedder is bound, or the embedder fails, the vector arm is left out and the result says `degraded: true`. The lexical arm binds the `all` form when some file in scope holds every term, and the `any` form otherwise. Each arm's candidate limit is `DEFAULT_ARM_LIMIT` (40), re-exported from `@memhtml/domain`, and the fused list is `MMR_POOL_FACTOR` times the hit limit, which is `DEFAULT_SEARCH_LIMIT` (10) unless the caller sets one. A step in `polarity.ts` then moves a candidate whose negation disagrees with the query below any candidate that agrees with the query and is near-identical to it in vector space, and MMR picks the final hits.

Each `SearchHit` carries its best chunk as a snippet, its entities as sorted `type:name` references, and `supersededBy`, read from an authored `supersedes` edge. The `SearchResult` also reports `vectorCoverage`, the `arms` that ran, and `entityScope`. When a narrowing scope finds nothing, `scopeEmpty` is true, and without `asOf` the `archivedMatches` count and its `ArchivedMatch` rows say what the same scope finds among archived files.

`recall` takes a `RecallInput`, runs the same fusion and polarity step over `DEFAULT_SEARCH_LIMIT` times `MMR_POOL_FACTOR` candidates without MMR, and folds them into a `RecallPack`. `foldDisclosure` walks the candidates in rank order and quotes each `DisclosureCandidate`'s disclosure text as a `DisclosedEntry` while it fits the character budget. A candidate that does not fit becomes an `IndexLine` with its path and claim, and the fold goes on, so a later, shorter memory can still be quoted. `MAX_PER_ENTITY` (2) caps the full quotes per entity name, and a capped memory still gets its index line. Arcs fold under their own `ARC_BODY_BUDGET` (9,000) and ordinary memories under the caller's `budgetChars` or `MEMORY_BODY_BUDGET` (16,000), so one synthesis cannot crowd out the memories behind it, and `budgetFor` picks between the two by type. Each `DisclosureFold` reports its quotes, its index lines, the characters spent, and whether anything was cut.

`readVectorCoverage` counts, in one statement, the chunks and the vectors in the configured space, or in the stored space when none is named, and returns a `VectorCoverage`. An index with no chunks has coverage 1. Retrieval leaves out the vector arm below `VECTOR_COVERAGE_FLOOR` (0.95) unless `RetrievalDeps` sets another floor, because when few files carry vectors, a vector rank on top of recency and salience can outscore an exact lexical match. `VectorCoverageLow` is a typed failure for coverage under a given floor, and `VECTOR_COVERAGE_HARD_FLOOR` (0.5) is a second, lower floor. A `VectorCoverageLow` reason names the counts and `VECTOR_COVERAGE_REMEDY`, plus `VECTOR_COVERAGE_NO_VECTORS_REMEDY` when the counted space holds no vector. `formatCoverage` prints a ratio as a percentage with at most one decimal.

`reinforce` bumps the `state.access` rows for a list of paths with one conditional upsert per `REINFORCE_PATH_BATCH` (500) paths. A path is bumped only when it has no recorded access or its last access is at least the cooldown old, 900 seconds by default from `@memhtml/domain`. SQLite decides that inside the statement and returns the rows it changed, so the `ReinforceResult` split into `bumped` and `cooledDown` holds for every process that calls `reinforce` on one store. Every bump raises the access count, and a bump whose signal is not neutral also raises the reinforcement count and moves the outcome score. A path's first row takes the signal's value, and after that each such bump moves the score by an EWMA with weight `OUTCOME_EWMA_ALPHA` (0.3), clamped between -1 and 1. Without a state plane it bumps nothing.

The state plane cannot be rebuilt from git, so the CLI's `state export` keeps its access rows in a committed file, `.memhtml/state/access.jsonl`, through the sidecar functions here. `accessRows` reads every `state.access` row as an `AccessRow`, ordered by path. `toSidecarEntry` turns a row into a `SidecarEntry`, with the outcome score rounded by `round4` to `SIDECAR_PRECISION` (4) decimals. `renderSidecar` writes one JSON object per line, so an unchanged table renders the same bytes. `parseSidecar` reads the file back one line at a time and counts, rather than fails on, a line it cannot parse, so a truncated file still restores the rows it holds. The file carries `state.access` only.

`persistScanned` writes one scanned transcript file, a `ScannedFileLike`, which is this package's structural copy of the scan result `@memhtml/traces` produces. A skip writes nothing. A rescan upserts the session's `traces` row and replaces its `trace_prompts`. For a tail, `readStoredExtract` reads the stored session, when there is one, and the injected `TailMerger` merges the tail into it before the same write. The row, its prompts and the file's watermark commit in one transaction, and the `PersistOutcome` says which path ran. `SessionExtractLike`, `PromptRowLike` and `WatermarkLike` are declared by structure, because `@memhtml/traces` depends on this package and not the other way round. `readWatermark` and `writeWatermark` convert between the scanner's epoch milliseconds and the table's ISO text. Retrieval never reads a trace table.

`makeIndexRecorder` returns the `IndexRecorderShape` behind the `IndexRecorder` tag. `recordLink` adds a `SessionLink`, whose kind is a `LinkKind` from `LINK_KINDS`, to `memory_session_links`, and an exact repeat adds nothing. `activePathForHash` is the dedup lookup the CLI hands to the store, with the same `memory_type <> 'task'` exclusion as the unique index it mirrors. `activeFramesFor` answers a whole set of frame keys in one query with the active non-task claims on each key, as `FrameMatch` rows. `activeNearestFor` reads the active memories' first-chunk vectors once and returns, for each query vector, at most `k` `NearMatch` rows at or above a cosine floor, best first.

The package publishes one import path, `@memhtml/index`, and its `index.ts` re-exports a chosen set of names, so the reference below is that set. A name a module exports that `index.ts` does not re-export is left off the page: all of `polarity.ts`, and helpers such as `rrfParams`, `buildFtsProbeSql`, `isBusyCause`, `toDiffEntry` and `toStatusEntry`.
