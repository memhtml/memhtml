`@memhtml/integrations` wires a coding agent to a memhtml store. For each host in `HOSTS` (Claude Code, Codex CLI, Cursor and OpenCode) and each scope in `SCOPES` (`user`, rooted at `$HOME`, or `project`, rooted at a git top level), it can write an MCP server entry, hooks, an instruction block and a skill, and it records what it wrote in a receipt. It renders text and edits files, and it opens no store itself; `doctor` starts the MCP server as a child process to check it. It depends on `@memhtml/contracts` for the recall discipline text, `effect` for its one error class, and `jsonc-parser` for JSON edits. Its one user is the CLI in `apps/cli`: the `memhtml integrations` commands, the `memhtml hook` engine that every installed hook runs, and the manifest and argument checks, which read `HOSTS` and `HOOK_EVENTS`. The CLI resolves `$HOME`, the project root and the store root and passes them in.

`hostSpec` gives the `HostSpec` for one host at one scope: the absolute path of each host file install touches, how each one is edited (`McpTarget`, `HooksTarget`, `InstructionTarget`), and the host's manual `nextSteps`. The hosts differ. Cursor gets no user-level instruction file, so `instruction` is `null` there, and at project scope it gets a whole-file rule, `.cursor/rules/memhtml.mdc`. OpenCode's hooks are a generated plugin file. Codex keeps its MCP entry in a fenced region of `config.toml`, a file people also edit by hand. Codex, Cursor and OpenCode share one skill file under `.agents/skills/memhtml/`. `detectHosts` returns, in `HOSTS` order, the hosts whose directory in `DETECT_DIRS` exists under `$HOME`, which is how `memhtml integrations install` with no host picks. `DEFAULT_TRACE_ROOT` gives only Claude Code a default transcript root, `~/.claude`, and the indexing hooks are written only when a root is known.

`cliCommand`, `mcpCommand` and `hookCommand` build every `CommandLine` from one `BinaryLocation`. By default the recorded node runs the recorded entry script, so the command does not depend on `PATH`; with `bare` the command is `memhtml` or `memhtml-mcp`. A hook runs the CLI with `hook <event> --host <host> --repo <store>`, plus `--trace-root` when `HookCommandOptions` names one. `shellJoin` and `shellQuote` turn a line into the shell string that Claude Code, Codex and Cursor store. `claudeMcpEntry`, `cursorMcpEntry`, `opencodeMcpEntry` and `codexMcpToml` render the MCP entry with the env they are given, which install fills with `MEMHTML_ROOT` only. In mode `none`, `claudeHooks`, `codexHooks` and `cursorHooks` return no hooks. Otherwise `claudeHooks` returns `SessionStart`, and in mode `all` it adds `UserPromptSubmit`, plus `PreCompact` and `SessionEnd` when there is a transcript root; `codexHooks` returns the first two only, and `cursorHooks` returns `sessionStart` alone. `claudeOwned`, also exported as `codexOwned` and `cursorOwned`, decides whether a hooks entry is ours: every command in it must have the `hook <event> --host <host>` shape and name the recorded entry script, or start with `memhtml hook` when installed bare.

`renderOpenCodePlugin` is OpenCode's hook surface: a generated module that imports only `node:child_process` and runs the recorded command itself. It wires `chat.message` for per-prompt recall in mode `all`, `experimental.session.compacting` to add the session-start pack to a compaction, and a `session.idle` indexer only when there is a transcript root. In the plugin, any error, nonzero exit or 1500 ms timeout counts as no output. `renderInstructionBlock` is the body of the block install fences into a host's instruction file: the store path, how to reach it, and the recall discipline from `@memhtml/contracts/guidance`. `renderCursorRules` wraps the same body as a Cursor rule with `alwaysApply: true`, and `renderClaudeImportBlock` is the `@AGENTS.md` import line. `renderSkill` renders `SKILL.md` with the same discipline and a table of CLI commands and MCP tools. `renderShellSnippet` and `rcFileFor` serve `memhtml integrations shell`, whose snippet exports `MEMHTML_ROOT` and adds a directory to `PATH` for a person at a terminal.

`renderHookOutput` is what `memhtml hook` prints for each host and event. Claude Code and OpenCode get plain text, Codex gets `hookSpecificOutput.additionalContext` JSON with the event names in `CODEX_EVENT_NAMES`, and Cursor gets an `additional_context` JSON object at session start. It returns the empty string for blank text and for an event the host takes no context on: compaction and session end on every host, and per-prompt on Cursor. `promptOf` and `cwdOf` read the prompt and the working directory from a host's hook payload, and `cwdOf` falls back to the first of Cursor's `workspace_roots`.

The file layer edits a shared file's text rather than parsing it and printing it again. `upsertJsonPath`, `removeJsonPath`, `upsertArrayEntries` and `removeArrayEntries` edit JSON or JSONC as text splices at `jsonc-parser` offsets, so comments, key order and the layout of other members stay as they were, and a document that does not parse is left without the edit. A removal that empties a nested object, such as `mcpServers`, takes that object out too, with any comment inside it. `fenced` builds the region operations behind the Markdown block (`upsertFencedBlock`), the Codex TOML region (`upsertFencedToml`) and the shell rc region (`upsertShellFence`): replace the lines between two marker lines, or append a new region. Duplicated, unpaired or out-of-order markers throw instead of being repaired. `hasUnfencedTable` finds a hand-written `[mcp_servers.memhtml]` table outside the fence. `writeTextAtomic` writes a temporary file beside the target and renames it into place, keeping an existing file's permission bits, so a reader of that file sees the old text or the new text. `snapshotText` and `restoreText` save and put back a file's text and mode. `assertNoSymlinkComponents`, which `install` runs on every target and on the receipt path, refuses a path when any part of it that exists is a symlink. `sha256` is the hash behind every receipt claim.

A receipt records what install owns, one per host per scope, at the path `receiptPath` names: `~/.config/memhtml/integrations/<host>.json` at user scope and `.memhtml-integrations/<host>.json` at a project's root. Each `ReceiptEntry` holds a path, a role from `MANAGED_ROLES`, a kind and the SHA-256 of the owned bytes. A `file` entry owns the whole file. A `fragment` entry owns a JSON key, a fenced region or the memhtml entries in a hooks object, inside a file other tools also write. `inspectReceiptFile` tells an absent receipt from a valid or an invalid one. Invalid covers text that is not a receipt, an entry path outside the receipt's `root`, and a receipt stored where its own host, scope and root would not put it. `readReceipt` folds absent and invalid into `null`, for readers that only display. `compareEntries` re-hashes each entry through a reader the caller supplies and answers `installed` or `modified`, with a `ReceiptDrift` row for each entry that changed or is gone. `receiptDriftReader` is that reader, built from the receipt alone through `editorFor`, and `install`, `uninstall`, `listIntegrations` and `doctor` all use it.

`planInstall` turns `InstallOptions` into an `InstallPlan`: one `PlannedWrite` per artifact, each carrying pure `apply`, `strip` and `ownedNow` functions of a file's current text. It reads disk only for the existing receipt and, for Claude Code at project scope, for `AGENTS.md` and `CLAUDE.md`: when `AGENTS.md` exists, the block goes there and `CLAUDE.md` gets an `@AGENTS.md` import, unless it already holds only that line. `install` runs one plan, for one host at one scope. It throws `IntegrationModified` and writes nothing when this host's receipt cannot be read or an entry in it no longer matches the disk, when something already sits where an artifact goes and that receipt does not claim it, or when Codex's `config.toml` has a hand-written memhtml table. With `force` it goes ahead and keeps the old text beside the file, in a copy named with `.memhtml-backup-` and a timestamp. An artifact whose bytes already equal the plan is not refused, which is how three hosts share one skill file. Then it snapshots every target, writes the files, and writes the receipt last. On a throw in that phase it restores the snapshots as best it can, removes its backups and rethrows. With `dryRun` it returns the `InstallReport` with each file's new text in `contents` and writes nothing. A run that would change nothing writes nothing, not even the receipt, and reports `changed: false`. A re-run with a narrower `hooks` mode removes, in the same call, the hooks that mode no longer wants.

`uninstall` removes what one host's receipt at one scope claims. It re-hashes every entry first and throws `IntegrationModified`, removing nothing, if any entry changed or is gone; it has no force option. It also throws, removing nothing, when the host's receipt, or another host's at the same scope, cannot be read. A path that another host's receipt at the same scope also claims, such as the shared skill, is left as it is. A file that is wholly ours, or that `strip` leaves empty, is deleted even if it existed before install, and the receipt goes last. With no receipt file the call succeeds as `not-installed` with `changed: false`. `listIntegrations` returns an `IntegrationRow` for each host at user scope, and at project scope when given a root. The state comes from the receipts and a re-hash of what they claim, never from a config entry that only looks like ours: a hand-written MCP entry with no receipt reads `not-installed`, and a receipt that cannot be read reads `modified`.

`locateBinary` resolves the `BinaryLocation` an install records: `process.execPath`, the entry script the caller passes, and the `memhtml-mcp` script found from it through `MCP_CANDIDATES` or named by `mcpOverride`, both scripts with symlinks resolved. It throws rather than return a location with no server. `doctor` checks one host at one scope against its receipt and returns a `DoctorResult` of `DoctorCheck` rows. The recorded binaries must exist, the CLI's `manifest` must report the recorded version, the store root must hold `.memhtml/`, every receipt entry must still match, the hooks, instruction block and skill must be present, and a transcript root that a hook names must be listable. Then the server must complete an MCP `initialize` handshake and give `MCP_SERVER_NAME` as its name. An absent or unreadable receipt returns one failing `receipt` row. The handshake is not attempted, and its row fails, when the store root has no `.memhtml/`, because starting the server would create one. The two checks that start a process go through `DoctorProbes`, which default to `spawnVersion` and `spawnHandshake`, bounded by `VERSION_TIMEOUT_MS` and `HANDSHAKE_TIMEOUT_MS`, and a caller can pass its own. Each probe gets a command line built from the receipt, so after a bare install the defaults run `memhtml` and `memhtml-mcp` from doctor's own `PATH`, not the recorded scripts. On Codex it adds a `hook-trust` row that is always `ok` and only reminds the operator to trust the hooks in Codex.
