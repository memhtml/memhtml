# memhtml · Business logic

> Generated from commit [`3406f7089918`](https://github.com/memhtml/memhtml/tree/3406f7089918528856905902284309cc11fc065d). Line citations refer to that commit.

Business logic in memhtml is the set of rules that decide what a memory record may be, where it lives, whether a write clears the store's bar, and how records are scored, fused and merged. Most of it lives in two pure libraries, `packages/contracts` (types, paths, slugs, edges, store policy) and `packages/domain` (scoring, ranking, merge and frame rules), and is enforced at the session validator, the store and the CLI and MCP write doors. This index covers rules enforced in TypeScript; SQL `CHECK` constraints in the index migrations are out of scope. Domain names follow the package sections of the [module map](../../architecture/module-map.md).

## Calculations

| Calculation                                                           | Inputs                                                      | Output           | Citation                                                                                                          |
| --------------------------------------------------------------------- | ----------------------------------------------------------- | ---------------- | ----------------------------------------------------------------------------------------------------------------- |
| Reciprocal rank fusion contribution `weight / (rank + 60)`            | rank, arm weight                                            | fused score      | `packages/domain/src/rrf.ts:28-29`, `packages/domain/src/ranking.ts:8`, `packages/index/src/retrieval-sql.ts:313` |
| Fused ranking: sum per path, score descending, path ascending on ties | arm hit lists, weights                                      | ordered paths    | `packages/domain/src/rrf.ts:39-65`, `packages/head/src/search.ts:233-234`                                         |
| Maximal marginal relevance with lambda 0.5                            | candidates, vectors, limit                                  | diversified list | `packages/domain/src/mmr.ts:36-89`, `packages/index/src/retrieval.ts:539`                                         |
| Cosine similarity, clamped to -1..1, 0 for a zero vector              | two vectors                                                 | similarity       | `packages/domain/src/cosine.ts:30-48`                                                                             |
| Retention composite score and keep/compress/evict band                | eight signals, per-type weight profile                      | score, action    | `packages/domain/src/retention.ts:239-276`                                                                        |
| Reprieve score                                                        | importance, access count, outcome score, hours since access | score            | `packages/domain/src/retention.ts:327-339`                                                                        |
| EWMA outcome and confidence decay in fixed point (scale 10,000)       | alpha, previous value, signals                              | new value        | `packages/domain/src/decay.ts:20`, `packages/domain/src/decay.ts:64-120`                                          |
| Reinforcement signal value: positive 1, negative -1, neutral 0        | signal                                                      | integer          | `packages/domain/src/reinforce.ts:39-48`, `packages/index/src/reinforce.ts:80-81`                                 |

RRF adds `weight / (rank + k)` per arm with `k` = 60 (`packages/domain/src/ranking.ts:8`); the lateral arm adds the same term using 1-based list position as its rank (`packages/domain/src/rrf.ts:75-87`). MMR picks, at each step, the candidate that maximizes `lambda * score - (1 - lambda) * maxSimilarityToSelected` (`packages/domain/src/mmr.ts:76`).

Retention computes each signal in 0 to 1 (`packages/domain/src/retention.ts:205-248`): recency is `exp(-ln2 * ageDays / halfLife)`, with half-lives of 10 days for episodic, 90 for semantic, 30 for arc, 14 for error_pattern, none for procedural and task, and 30 for an unlisted type (`:110-129`); access frequency is `min(1, accessCount / 10)`; bridge importance and reinforcement are each `min(1, count / 5)`; content density is `words^2 / 1000` under 10 words and `min(1, words / 100)` otherwise; contested status is `1 - min(1, contradictions / 3)`; pagerank is graph rank over the max graph rank. The composite is the compensated weighted sum, rounded to 4 decimals (`:255-259`), and the band is keep above 0.7, compress above 0.3, evict otherwise (`:144-145`, `:265-269`).

The reprieve score is `0.4 * clamp(importance, 1, 10) / 10 + 0.3 * ln(1 + accessCount) + 0.2 * max(0, outcome) + 0.1 * exp(-0.01 * hoursSinceAccess)` (`packages/domain/src/retention.ts:295-301`, `:327-339`). One EWMA step is `floor((alpha * signal + (SCALE - alpha) * prev) / SCALE)` (`packages/domain/src/decay.ts:64-65`); confidence decay steps toward a floor of 0.2 with alpha 0.1 and never raises confidence (`:38-46`, `:102-103`).

The retention, reprieve, decay and merge calculations have no importer outside `packages/domain`: the list of files that import `@memhtml/domain` (`rg -l 'from "@memhtml/domain"' apps/*/src packages/*/src`) names only frame, cosine, RRF, MMR, reinforcement and negation imports. They're defined and tested, but no production path calls them at this commit.

## Policy and gates

- **Write bar, refused types:** a session put whose memory type is in `writeBar.refusedTypes` is refused with the configured or default reason; archive destinations are exempt. `packages/session/src/validate.ts:159-173`, `packages/contracts/src/store-config.ts:152-163`
- **Write bar, anchor rule:** with `writeBar.requireAnchor` on, a new, moved or unlabeled record must name an entity or live under `projects/`. `packages/session/src/validate.ts:138-140`, `packages/session/src/validate.ts:555-572`
- **Write bar defaults:** with no config file, nothing is refused and no anchor is required. `packages/contracts/src/store-config.ts:118-121`
- **v1 doors:** the direct record-creating CLI and MCP commands run `guardV1Door`; mode `open` always passes, any mode refuses inside a run session except `open`, and `closed` refuses outside one too. The default is `closed-in-session`. `apps/cli/src/store-config.ts:155-177`, `packages/contracts/src/store-config.ts:123`
- **Curator placement quota:** the curator caps the inbox records a run files at `inboxCapFor(placementQuota)`, where `curator.placementQuota` defaults to 60. `packages/contracts/src/store-config.ts:48`, `packages/curator/src/inbox.ts:244-245`, `packages/curator/src/briefing.ts:450`
- **Curator writer buckets and refused types:** a home that matches a `curator.writerBuckets` glob counts as a bucket home, and a refused type is never chosen as a cluster's canonical type. `packages/curator/src/planner/plan.ts:85-89`, `packages/curator/src/planner/plan.ts:115-120`
- **Placement:** a record without a valid explicit path goes to `areas/arcs` for an arc, `projects/<workspace>/tasks` or `areas/inbox/tasks` for a task, `projects/<workspace>` when a workspace is given, `resources/<tag>` for semantic, procedural or precedent with a tag other than `people`, and `areas/inbox` otherwise. `packages/contracts/src/paths.ts:148-187`
- **Episodic filenames:** an episodic record's filename carries a `YYYYMMDD-` UTC date prefix. `packages/contracts/src/slug.ts:133-148`
- **Reinforcement cooldown:** an access bump for a path is skipped when the last one was under 900 seconds ago; a neutral signal records access without reinforcement. `packages/domain/src/ranking.ts:24`, `packages/domain/src/reinforce.ts:20-28`, `packages/index/src/reinforce.ts:74-81`
- **Near-duplicate detection:** a CLI write op whose embedding has cosine at or above 0.92 against a store record or an earlier op in the batch is reported as a near duplicate. `packages/domain/src/merge.ts:22`, `apps/cli/src/operations.ts:695-705`
- **Merge gate:** a merge pair commits only under the 100-pair cap, above the 0.92 threshold, and when negation, numeric-token and variant-qualifier checks all agree. `packages/domain/src/merge.ts:22-25`, `packages/domain/src/merge.ts:207-225`, `packages/domain/src/merge.ts:280-295`
- **Polarity:** retrieval flags a result whose negation markers disagree with the query's. `packages/index/src/polarity.ts:84`, `packages/domain/src/merge.ts:168-172`
- **Frame agreement:** a group of records with the same frame key agrees when their frame values or normalized claims match, except that verdicts with different titles never agree. `packages/domain/src/agreement.ts:30-42`, `packages/domain/src/frame.ts:67-78`
- **Reprieve:** an eviction candidate is reprieved when its reprieve score is at least 0.5 and it has had fewer than 3 reprieves. `packages/domain/src/retention.ts:282-292`, `packages/domain/src/retention.ts:346-353`
- **Confidence commit threshold:** a confidence change under 0.005 isn't worth committing. `packages/domain/src/decay.ts:146-150`
