# memhtml-public · Debugging guide

When something is broken, this file says where to look first.

Two facts shape every entry below. First, the debugger is usually an agent, so the signal it reads is a JSON envelope on stdout plus an exit code. Every command writes exactly one envelope to stdout and sends logs to stderr (`apps/cli/src/run.ts:1029-1031`), and a failure envelope is `{apiVersion, error, code, suggestions}` (`apps/cli/src/envelope.ts:55-60`). An agent branches on `code` and not on the `error` prose, because the codes are append-only and the prose changes freely (`apps/cli/src/envelope.ts:62-66`).

Second, the state being debugged is not in this repository. This repo holds the software. The memories live in an external `memhtml root` directory that `$MEMHTML_ROOT` points at, defaulting to `~/memhtml` (`RUNBOOK.md:13`). The same binary serves many roots, and `--repo <path>` overrides the variable per call (`RUNBOOK.md:22`). "The tree is dirty" therefore refers to the root's git tree, and `.memhtml/index.db` inside the root is a rebuildable projection of that tree rather than a store of record.

There is no observability platform in this codebase. `Effect.withSpan` wraps 29 call sites, but no exporter is configured and no `opentelemetry` dependency exists in any workspace package. Every diagnostic below reads stderr, a JSON envelope, or a file in the root.

## Failure-mode index

| Symptom | Likely surface | First check | Citation |
|---|---|---|---|
| Search returns results but the good one ranks low, and nothing errored | The vector arm is absent, so retrieval assembled on the lexical, recency, and salience arms alone. A model failure is caught, and the search degrades instead of failing. | Read `degraded` on the search response. `true` means the query embedder returned nothing. | `packages/index/src/retrieval.ts:189-200`, `packages/index/src/retrieval.ts:390` |
| Every command that writes to the index fails with `ERR_EMBED_MODEL_MISMATCH`, and a rebuild does not clear it | The stored vector space disagrees with the configured one. `guardEmbedModel` runs before any write in both `rebuild` and `update`, so an index built under one model can never accumulate rows under another. | `memhtml status` and read `embedModel` against the configured watermark. A rebuild alone does not clear this; the database file has to go first. | `packages/index/src/indexer.ts:212-217`, `RUNBOOK.md:113-119` |
| A newly written memory is absent from search results | The index describes an older commit. The index is a projection of a commit, so fresh means the commit it describes is the commit the root is on. | `memhtml status` and read `indexFresh`. `false` means run `memhtml index update --embed`. | `apps/cli/src/operations.ts:1776`, `apps/cli/src/operations.ts:1729-1731` |
| `memhtml sleep run` refuses in phase one with `ERR_DIRTY_TREE` | Preflight calls `requireCleanTree()`. A phase reading the index while the root's tree holds uncommitted edits would curate a corpus that exists nowhere. | `git -C "$MEMHTML_ROOT" status --porcelain`. The refusal lands before any phase commits, so nothing needs undoing. | `packages/sleep/src/phases/preflight.ts:22`, `RUNBOOK.md:262` |
| A write fails with `ERR_WRITE_CONFLICT` naming two blob shas | Two writers touched the same file in the root. The caller recovers by re-reading the current content and reapplying the change. | `memhtml read <path>` for the current content, then re-apply the change. The suggestion already names the path. | `packages/contracts/src/errors.ts:13-22`, `apps/cli/src/errors.ts:130-133` |
| A command fails with `ERR_STORAGE` and the payload names only an operation | A SQLite driver or filesystem rejection. The typed error excludes SQL text, parameters, and row contents, so a storage error can reach an agent without carrying corpus content. | Read stderr for the `db.<operation> failed:` line, which carries the driver's own message. The envelope does not carry it. | `packages/contracts/src/errors.ts:3-11`, `packages/index/src/database.ts:164-170` |
| Concurrent writers occasionally stall for up to 20 seconds, then succeed | Contended SQLite writes. `busy_timeout` covers a short wait inside one call; past its deadline a jittered exponential retry from 15ms up to 20 seconds takes over, gated on numeric `errcode: 5`. | Reproduce with `node scripts/probe-sqlite-concurrency.mjs`. Retrying is safe because the lock was never taken, so the statement had no effect to half-apply. | `packages/index/src/database.ts:155-158`, `packages/index/src/database.ts:151-153` |
| Conflict markers appear inside a generated `index.html` or `sitemap.xml` in the root | The `merge=ours` attribute is set but the `merge.ours.driver` git config is missing. The attribute alone does nothing, as probed live on 2026-08-02. Git config is per-clone and is not cloned. | `git -C "$MEMHTML_ROOT" config --get merge.ours.driver`. It must print `true`. If it does not, run `memhtml init`. | `packages/store/src/layout.ts:65-69`, `RUNBOOK.md:42` |
| Every MCP tool failure reads "Tool execution failed due to an internal server error" | A handler failed with something other than the declared `ToolFailure`. Effect's `McpServer` has three catch branches for a failed `tools/call`, and only the branch matching the tool's own `failure` schema passes prose through verbatim. | Confirm each tool in `apps/mcp/src/tools.ts` still declares `failure: ToolFailure`. Dropping the declaration re-masks everything `toToolFailure` builds. | `apps/mcp/src/failure.ts:6-20`, `apps/mcp/src/handlers.ts:58-64` |
| `memhtml eval discriminate` reports `passed: false` with zero probes | Live mode ran without `AWS_BEARER_TOKEN_BEDROCK`. Nothing was measured. The skip is reported as a failure by design, so a pipeline cannot report green over an unmeasured gate. | Read `skipped` on the response. `true` means re-run with credentials or run `--mode fake`, which is the mode CI measures. | `packages/eval/src/run.ts:85-95`, `RUNBOOK.md:205` |
| `memhtml sleep merge` returns a report with `refusal: "gate-failed"` and no merge | The discrimination gate refused because the run degrades retrieval. The refusal is a value on the report rather than an error. | `memhtml eval discriminate` to see which probes inverted, then `git branch -D <run-id>`. `main` never moved. | `packages/sleep/src/contract.ts:169`, `RUNBOOK.md:189` |
| A sleep run reports a `failed` phase but later phases still ran and committed | This is the designed behavior. Each phase is its own commit, and a failure is caught as a value the loop reads, so prior commits survive on the `sleep/<date>` branch. | `memhtml sleep status` for the per-phase outcomes. The one exception is `dedup-merge`, whose failure skips `compress` and `retention-triage`. | `packages/sleep/src/run.ts:231-240`, `packages/sleep/src/contract.ts:57` |
| A search query errors instead of returning zero results | The FTS sanitizer was bypassed. An apostrophe, a `type:name` entity reference, and a leading hyphen each produce a hard driver error instead of an empty result, and an empty MATCH is itself the syntax error `fts5: syntax error near ""`. | Confirm the query passed through `sanitizeFtsQuery` before reaching MATCH. A query that errors is a bug rather than a configuration problem. | `packages/index/src/fts-query.ts:36-42`, `RUNBOOK.md:260` |
| `memhtml exec` returns exit 0 with a script that clearly failed | This is the designed behavior. A non-zero guest exit is reported as data. The envelope carries `exitCode` and `stderr`, so an agent debugging a selector reads the script's own diagnostic instead of an `error` string. | Read `data.exitCode` and `data.stderr` on the success envelope. Only the runtime's own failures take the error channel and become exit 1. | `apps/cli/src/exec.ts:196-205`, `apps/cli/src/commands.ts:1010` |
| Trace consolidation reports `ok` night after night and no memories appear | Four different situations report `ok`, and only one of them means the transcripts were consolidated. The `detail` field tells them apart. | Read `counts.batch` against `counts.consolidated`. A nonzero `batch` with `consolidated: 0` means the transcripts are still waiting. | `RUNBOOK.md:166-175`, `packages/sleep/src/phases/trace-consolidation.ts:322-323` |
| An access count in the root goes down after a `git pull` | `.memhtml/state/access.jsonl` is a whole-file merge, so two machines' access counts do not combine. The later commit wins and the other machine's reads are lost. No alarm fires on it. | Compare access counts across the pull. The mitigation today is to keep one writer, so a second machine should run `memhtml state import` and never `memhtml state export`. | `RUNBOOK.md:134-138`, `apps/cli/src/state.ts:54` |

## Log and error surfaces

| Surface | Where it emits | What to grep for | Citation |
|---|---|---|---|
| The JSON envelope | stdout, exactly one per command, nothing else | `"code":"ERR_` for a failure; `"apiVersion"` is on both shapes | `apps/cli/src/envelope.ts:55-60`, `apps/cli/src/run.ts:1017-1019` |
| Exit code | The process status | `0` success, `2` usage error the caller fixes by changing the call, `1` runtime failure the caller fixes by changing the root or the environment | `apps/cli/src/envelope.ts:88-90`, `apps/cli/src/commands.ts:851-852` |
| CLI effect logs | stderr, always. The default effect logger writes to stdout, which would interleave log lines with the envelope and break every parser | `level=WARN` and `level=ERROR`; 25 `logWarning` and 14 `logError` sites across the codebase | `apps/cli/src/run.ts:1029-1031` |
| MCP server logs | stderr, by a provided `Logger.LogToStderr` reference. stdout on this transport is the NDJSON-RPC stream, so one log line would corrupt the frame a client is mid-parse on | `ERR_` prefixes and tool names; `Effect.tapCause(Effect.logError)` runs before all three `McpServer` catch branches | `apps/mcp/src/server.ts:20-22`, `apps/mcp/src/server.ts:53` |
| Storage driver detail | stderr only, not the envelope | `db.` followed by the operation name and `failed:` | `packages/index/src/database.ts:164-170` |
| Git subprocess stderr | stderr only, not the envelope. `GitFailure` carries the subcommand name and exit code, because arguments carry memory paths and commit subjects carry memory titles | `git ` followed by the subcommand and ` exited ` | `packages/store/src/git.ts:219-221`, `packages/store/src/git.ts:28-38` |
| The MCP wire failure text | The tool-error text block an agent reads. `code` and `suggestions` are folded into one string, because MCP's tool-error channel is one text block | The `ERR_*` prefix, which comes first and is followed by a colon so a consumer can read the code back out | `apps/mcp/src/failure.ts:20-23`, `apps/mcp/src/failure.ts:168-175` |
| Skipped quality gate | stderr at `logError` level rather than `logWarning`, because operators filter out warnings | `eval discriminate:` followed by `did NOT run` | `packages/eval/src/run.ts:90-95` |
| Doctor report | The success envelope on stdout. Every list is present and possibly empty, so a parser does not branch on presence | `"healthy":false`, then the finding lists: `dangling`, `orphanAccessRows`, `unparseable`, `warnings` | `apps/cli/src/doctor.ts:111-143` |
| Status report | The success envelope on stdout | `"indexFresh"`, `"embedderUp"`, `"dirty"`, `"lastSleep"` | `apps/cli/src/operations.ts:1764-1788` |
| Sleep run report, on disk in the root | `.memhtml/sleep/<run-id>.html`, committed by phase 15 | The per-phase `status` and `detail` values | `packages/sleep/src/report.ts:6`, `packages/sleep/src/phases/report.ts:11` |
| Sleep phase trailers, in git history | `Memhtml-Phase` commit trailers on the `sleep/<date>` branch in the root. A resume reads these rather than the `sleep_phases` table, because a process killed after `git commit` and before the row write makes the two disagree | `git -C "$MEMHTML_ROOT" log --format=%B` for `Memhtml-Phase` | `packages/sleep/src/run.ts:140-145` |
| Cron log files | Whatever the cron line redirects to. The RUNBOOK's example lines send each command to its own file under `/var/log/memhtml/` | The envelope's `code` field per line, because each run appends one envelope | `RUNBOOK.md:69-73` |

## First-checks ladder

The checks are ordered cheapest first. Each one either explains the symptom or rules out a layer.

1. Run `memhtml manifest` and confirm it answers. It returns every command, argument, flag, response type, error code, and environment variable. It answers on a machine with no repo, no database, and no credentials, which makes it the liveness check when something else has failed. `apps/cli/src/commands.ts:843-846`
2. Read the failure envelope's `code` instead of its `error` prose. The codes are append-only and a shipped code never changes meaning, while the prose changes freely as wording improves. Fifteen codes exist, and an unrecognized upstream error class becomes `ERR_UNKNOWN` instead of crashing. `apps/cli/src/envelope.ts:67-83`, `apps/cli/src/errors.ts:41-42`
3. Read the envelope's `suggestions` array and run the first entry. Suggestions are part of the contract. An agent that receives `ERR_INDEX_STALE` and a `memhtml index update` suggestion recovers in one step without a round trip to a human. When there are no suggestions the field is an empty array rather than a null. `apps/cli/src/errors.ts:111-116`
4. Confirm which root the command acted on. `memhtml status` reports `root`. The same binary serves many roots, with `$MEMHTML_ROOT` setting the default and `--repo <path>` overriding it per call. A memory that seems missing is often present in a different root. `apps/cli/src/operations.ts:1765`, `RUNBOOK.md:22`
5. Read `indexFresh` and `embedderUp` from `memhtml status`. `indexFresh` compares the recorded watermark to HEAD, which is the accurate comparison because the index is a projection of a commit. `embedderUp` is read off the stored watermark instead of by probing Bedrock, so it does not fail for a reason unrelated to the corpus. `apps/cli/src/operations.ts:1776`, `apps/cli/src/operations.ts:1782`
6. Run `memhtml doctor` for the eight corpus checks. `healthy` is computed from the findings rather than from a repair. `overdueTasks` and `staleBlockers` do not count toward it, because those two describe the state of the work rather than defects in the corpus. `apps/cli/src/doctor.ts:484-500`
7. Read stderr for the layer the envelope withheld. Each typed error class drops the driver message, the SQL, the git argv, and every memory body at its adapter edge, so a tool response cannot carry corpus content. The detail goes to `Effect.logError` instead. `packages/contracts/src/errors.ts:3-8`, `packages/index/src/database.ts:164-170`
8. If the symptom is retrieval quality with no error at all, run `memhtml eval discriminate`. Every probe must outrank its own wrong-fact twins against an MRR floor of `0.85`, and a failing run is reproducible from its `seed`. `packages/eval/src/discriminate.ts:103`, `RUNBOOK.md:203`
9. If the index looks structurally wrong, rebuild it. `memhtml index rebuild --embed` drops the FTS index, deletes every memory table, reprojects, and recreates the index. It deletes nothing outside `.memhtml/`, and it touches neither the trace tables nor the attached state plane. A deleted database mostly handles itself, because `update` with no recorded watermark falls through to a rebuild. `packages/index/src/indexer.ts:539-540`, `RUNBOOK.md:111`
10. As a last resort, reclone the root and reproject. Run the steps in this order. `memhtml init` comes first because the merge driver is per-clone. `memhtml state import` comes before the rebuild so the salience arm has signal on the first query. `memhtml index rebuild --embed` comes last because it is the only step that costs Bedrock calls, and it is the step to re-run if the sequence is interrupted. `RUNBOOK.md:272-286`

## Known incident patterns

This codebase carries no `INCIDENT:` or `POSTMORTEM:` comment tags and holds exactly one file under `docs/bugs/`. Its history is recorded inline at the site of each fix, describing what used to be broken, what broke, and what prevents it now. Those records are the entries below.

- **AiError masking on the MCP boundary:** `handled` used to build an `AiError`, and `McpServer` catches `AiError` first and rewrites it to a generic internal-error sentence unless its reason is a parameter-validation error. Signal: every typed failure reached its agent with the content removed. Mitigation: a `ToolFailure` that each tool's `failure:` schema declares, which puts it on the branch that passes `.message` through verbatim. The two halves work only together, and dropping the declaration in `apps/mcp/src/tools.ts` re-masks everything the translation builds. `apps/mcp/src/handlers.ts:58-64`
- **Watermark over the asked-about set rather than the read set:** trace consolidation used to watermark `batch`, the sessions the phase asked about, instead of the sessions the agent read. The two differ whenever a transcript does not reach the agent, which happens when it was rotated away since `memhtml trace index` ran, moved outside `MEMHTML_TRACE_ROOT`, or placed behind a symlink the read-only mount will not follow. Signal: a session recorded as consolidated that nothing had read. Because `trace_consolidations` is an anti-join, that transcript was never selected again. Mitigation: a structural guard instead of a check, because `ConsolidationOutcome` cannot be constructed without `analyzedSessionIds`. `packages/sleep/src/phases/trace-consolidation.ts:437-455`
- **Stale suggestions naming renamed commands:** a command rename in `apps/cli/src/commands.ts` used to leave a suggestion in `apps/cli/src/errors.ts` naming a command that no longer existed, and nothing failed on it. Signal: an agent following a suggestion into `ERR_UNKNOWN_COMMAND`. Mitigation: `SUGGESTIONS` is a record instead of a switch, because a record's keys and arms are both walkable. The suite enumerates every tag, runs every suggestion through the real `parseArgv`, and fails on a name the command table does not hold. `apps/cli/src/errors.ts:117-122`
- **Empty `<mark>` passing the render gate:** the count rule and the placement rule left a hole an empty claim span fit through, so `<p><mark></mark> the prose</p>` used to land a committed, indexed file with an empty `files.gist`. Signal: a memory absent from every disclosure tier and from the recall pack's quoted body, so it did not appear at all rather than appearing wrong. Mitigation: a non-empty rule in the gate itself, with both write doors deriving a claim from prose as a second layer. `packages/html/src/constraints.ts:158-163`
- **`files.event_at` unreachable through every write path:** filed and resolved 2026-08-03. Both write surfaces escaped the entire body as text, so a `<time datetime>` element an agent supplied reached disk as literal escaped text. `event_at` stayed NULL, and the recency arm's `coalesce(event_at, updated_at)` fell back to write time on every agent-written memory. Signal: episodic memories sorting by when they were written down instead of when the fact happened. Mitigation: an `articleHtml` passthrough exclusive with the prose path, guarded by a render gate in `@memhtml/store` that re-parses every write before anything is staged or committed. `docs/bugs/2026-08-03-event-at-unreachable-through-write-paths.md:1-18`
- **Anonymous consolidator agent endpoint:** the agent channel used to authenticate every caller with `none()`, so the bind address was the only thing keeping it off the network. Signal: any local UID could drive the session endpoint for a run's duration, which gives free Opus tokens plus a bash sandbox whose full network egress this app cannot turn off. Measured 2026-08-09 via `node scripts/probe-sandbox-egress.mjs`: `curl` reaches example.com, and an IMDSv2 token PUT returns the instance-role name. Mitigation: an HS256 bearer JWT over a secret minted per spawn, with the loopback bind kept as the second layer. `apps/consolidator/src/run-auth.ts:6-20`
- **Store-scaled per-batch costs that made bulk ingest quadratic:** two separate instances. A per-file tree walk cost 2N tree walks for a batch of N writes, probed 2026-08-05 at 49ms per walk over 10k files, which was 25 seconds of a 48-second update at N=256. The other was an unscoped pending-embedding scan, measured linear at 11ms over 1k chunks and 60ms over 10k. Signal: an incremental `index update` whose duration grew with corpus size instead of with batch size. Mitigation: one full-tree walk plus a batched blob read, and a pending scan scoped to the batch's own chunks. `packages/index/src/indexer.ts:560-570`, `packages/index/src/indexer.ts:236-246`
- **Guards kept because a mutation turned them off:** two doctor predicates were mutation-verified on 2026-08-02 instead of assumed. Dropping `archived = 0` and `task_status <> 'done'` from the overdue-task query makes the finding grow forever and never reach zero, because a finished task's deadline stays in the past. The `missing` arm of the stale-blocker check is unreachable today, because deleting a blocker's file makes `indexer.update` clear `edges WHERE src_path = ?` in the same batch. It stays because `edges` carries no foreign key by design, so a future writer of edge rows would not inherit the indexer's discipline. `apps/cli/src/doctor.ts:213-215`, `apps/cli/src/doctor.ts:245-250`
