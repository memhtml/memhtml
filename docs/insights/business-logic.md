# memhtml-public · Business logic

Describes the source at memhtml 0.15.1 (main `f70e60a`, 2026-09-16). Citations are `path:line` into that tree.

This file indexes the domain rules the codebase enforces and names the line that enforces each one. The rules govern memory management: what counts as a valid memory file, what a write may and may not do to the managed tree, how a memory's weight is computed, and which gates a curation run must clear before it lands.

**Scope.** In scope: application-layer validations, invariants, calculations, and policy gates in `packages/` and `apps/cli`, `apps/mcp`, `apps/consolidator`. The SQLite `CHECK` and uniqueness constraints in `packages/index/migrations/` are also in scope, because several of them are the only enforcement point for a rule the application relies on, and because the application's own predicates are written to agree with them. Out of scope: the `apps/docs` Astro package, test fixtures, and build tooling.

**Two facts a reader needs before reading a rule.** First, this repository stores no memories. It is the software that manages a separate directory, the `memhtml root`, located by `$MEMHTML_ROOT` (`apps/cli/src/config.ts:63-67`). Every rule below acts on whatever root the environment points the binary at. The root's git tree is the system of record and `.memhtml/index.db` inside the root is a rebuildable projection of it. Second, a coding agent is the primary consumer of these surfaces. The rules are shaped for that consumer. The CLI answers in a versioned JSON envelope with a stable error code an agent branches on (`apps/cli/src/envelope.ts:76-116`), the MCP server publishes a JSON Schema per tool, and the format constraints are stated in tool descriptions so an agent learns a rule before it spends a round trip discovering it (`apps/mcp/src/tools.ts:132-161`).

**Violations are collected rather than short-circuited.** `checkDocument` runs every check and concatenates the results, so one parse tells an author everything wrong with the file rather than the first thing (`packages/html/src/constraints.ts:358-369`). Violations join into a single `InvalidMemory.reason` with `"; "` (`packages/html/src/constraints.ts:39-40`). Nothing in the checker throws and nothing repairs a violation, because a checker that silently fixed one would make `memhtml doctor` report a clean corpus that the next hand-edit breaks again (`packages/html/src/constraints.ts:35-37`).

**Constraints 1 through 5 refuse; constraint 6 warns.** A file using an element outside the closed vocabulary still indexes, because the format has to degrade gracefully on a file a human hand-wrote in a hurry (`packages/html/src/constraints.ts:28-37`). Warnings are deduplicated by element name, so a file with forty stray `<div>` elements produces one actionable line (`packages/html/src/constraints.ts:324-334`).

**What depends on the hash invariant.** Confidence decay, access bookkeeping, and every sleep-phase stamp write to the head. If any of them moved the content hash, each corpus-wide decay pass would present the whole corpus as new content and dedup would collapse (`packages/html/src/hash.ts:7-16`). Two mechanisms hold the invariant. First, the digest is taken over `<article>` text only, and the article is located first so head content can never reach it (`packages/html/src/hash.ts:151-161`). Second, every head edit goes through byte-splicing editors rather than a parse-and-serialize round trip, which would drop a `<pre>` newline per write (`apps/cli/src/doctor.ts:86-92`). The sleep review surface then reads the invariant back out. A modification is classified `meta-only` when the two versions' article hashes agree, which is computed rather than inferred from the diff (`packages/sleep/src/review.ts:177-188`).

### The fixed-point grid and the two EWMAs

All confidence and outcome arithmetic runs on an integer grid at scale 10^4, so the grid step is the fourth decimal place (`packages/domain/src/decay.ts:19-20`). The grid is there to make the module's boundary claims exact, and it was not chosen for speed. Every invariant in the module is a boundary claim: decay stops at the floor, `alpha = 1` snaps exactly to it, and `alpha = 0` is exactly a fixed point. In float arithmetic a convex combination of two equal values can land one unit in the last place below them, so those claims would hold only approximately and would fail as written (`packages/domain/src/decay.ts:11-16`).

One EWMA step is `alpha * signal + (1 - alpha) * prev`, divided back down with floor division (`packages/domain/src/decay.ts:64-65`). Floor is used rather than round-half-away, because floor is the one rounding mode whose N-fold composition is reproducible without a rounding-mode argument, and the residual drift against an unrounded fold is bounded by one grid step (`packages/domain/src/decay.ts:54-58`). Rounding happens inside the fold rather than once at the end, which is what makes an N-signal batch agree with N single-signal calls. Sleep may process one memory's corrections in a single batch or across several runs, and it must reach the same score either way (`packages/domain/src/decay.ts:67-72`).

The two alphas differ. The outcome EWMA weights an incoming reinforcement at 0.3 (`packages/domain/src/decay.ts:26-31`). Confidence decay weights the pull toward the floor at 0.1, so a claim closes a tenth of its distance to the floor per unreinforced sleep cycle (`packages/domain/src/decay.ts:40-46`). Confidence should erode over many unreinforced runs rather than collapse in one, so a single missed reinforcement costs little.

The confidence decay step is an EWMA toward the floor followed by a `min` with the previous value (`packages/domain/src/decay.ts:102-103`). The `min` is what makes the step unconditionally non-increasing. Without it, a claim already below the floor, such as one an operator correction pushed down, would be pulled back up toward the floor by the same convex combination that erodes a healthy claim, so decay would rehabilitate a discredited memory (`packages/domain/src/decay.ts:92-101`). The floor is 0.2 rather than 0, because an old uncorroborated claim is weak evidence and a memory decayed to 0 would be indistinguishable from a retracted one (`packages/domain/src/decay.ts:33-38`).

### The eight-signal retention score

Each memory's retention score is a weighted sum of eight normalized signals, in this fixed order: recency, access frequency, confidence, PageRank, bridge importance, reinforcement count, content density, and contested status (`packages/domain/src/retention.ts:8-18`).

The normalization curves live in one place (`packages/domain/src/retention.ts:204-248`):

- **Recency** is `exp(-LN2 * ageDays / halfLife)`, and a `null` half-life or a non-positive age means no decay (`packages/domain/src/retention.ts:204-209`). The curve uses `Math.LN2` rather than a `0.693` literal, so the value is exactly 0.5 at one half-life and the half-life defines the curve instead of approximating it (`packages/domain/src/retention.ts:131-137`). Half-lives in days: episodic 10, semantic 90, arc 30, error_pattern 14, procedural `null`, task `null` (`packages/domain/src/retention.ts:106-126`). An unlisted type takes 30 days (`packages/domain/src/retention.ts:128-129`).
- **Access frequency** saturates at ten accesses (`packages/domain/src/retention.ts:211-212`).
- **PageRank** is the memory's rank over the run's corpus maximum, so the signal is corpus-relative rather than absolute, and 0 when the maximum is 0 (`packages/domain/src/retention.ts:243`).
- **Bridge importance** saturates at five community-crossing edges (`packages/domain/src/retention.ts:214-215`).
- **Reinforcement count** saturates at five inbound reinforcements (`packages/domain/src/retention.ts:217-219`).
- **Content density** uses word count as a proxy. 100 words saturates on the main `wordCount / 100` line. A body under 10 words takes the quadratic arm `wordCount^2 / 1000`, which ranges over `[0, 0.081]` and joins the main line exactly at 10 words, so the whole signal is monotone nondecreasing in word count and a terse memory can never out-score a longer one on it (`packages/domain/src/retention.ts:221-232`).
- **Contested status** is inverted and floors at 0 from three contradictions (`packages/domain/src/retention.ts:234-236`). It counts only authored contradictions, so a sleep-mined suspicion can never evict a memory (`packages/domain/src/retention.ts:164-165`, `packages/contracts/src/edges.ts:122-128`).

The composite is the compensated sum of `signal * weight` over the eight, rounded to four decimals (`packages/domain/src/retention.ts:250-259`). Five per-type weight profiles are declared, plus a default for every other type (`packages/domain/src/retention.ts:32-104`). Every profile's eight weights sum to exactly 1.0 under compensated summation, which makes the composite a convex combination of eight `[0, 1]` signals and therefore itself in `[0, 1]` (`packages/domain/src/retention.ts:195-200`). The profiles encode a per-type judgement. Recency carries the most weight for `episodic`, where time is the type's identity, and exactly zero for `procedural`, because a working procedure does not go stale (`packages/domain/src/retention.ts:36-40`).

The bands are `keep` above 0.7, `evict` at or below 0.3, and `compress` in the open interval between (`packages/domain/src/retention.ts:139-145`, `:261-269`). Each boundary is owned by the lower band, so exactly 0.7 compresses and exactly 0.3 evicts, and the three bands partition `[0, 1]` with no score left unbanded.

### The four-term reprieve score

A memory whose `memhtml-valid-until` has passed either earns another two weeks or expires. The score is `0.4 * (importance / 10) + 0.3 * log1p(accessCount) + 0.2 * max(0, outcomeScore) + 0.1 * exp(-decayRate * hoursSinceAccess)` (`packages/domain/src/retention.ts:327-339`). Coefficients at `packages/domain/src/retention.ts:297-301`. Salience decay rate 0.01 per hour (`packages/domain/src/retention.ts:294-295`).

The four coefficients sum to 1.0, but the score is still not convex, because the `log1p(accessCount)` term is unbounded and the score can therefore exceed 1 (`packages/domain/src/retention.ts:297`, `:318-320`). It is proven only monotone and sign-clamped, which is all the gate needs. A negative outcome score contributes exactly 0 rather than a penalty, mirroring the salience arm's own clamp. Without that clamp a memory that once produced a bad outcome would be punished twice, once by the outcome EWMA that already lowered its salience and again here (`packages/domain/src/retention.ts:322-325`).

The gate reprieves a TTL-passed memory when its score clears the floor of 0.5 and it has been reprieved fewer than three times (`packages/domain/src/retention.ts:278-292`, `:341-353`). The cap is what gives the TTL force. Without it a frequently-read memory would extend its own validity forever, and `memhtml-valid-until` would document an intention the system never enforces (`packages/sleep/src/phases/reprieve.ts:19-22`). `maxReprieves: 0` is the kill switch that restores pure-age TTL. It works because the score is a sum of non-negative terms and so is always above 0, meaning the floor alone can never force expiry (`packages/domain/src/retention.ts:287-292`).

### Reciprocal rank fusion and MMR

Each retrieval arm produces its own ranked candidate list and contributes `weight / (rank + k)` per hit, with `k` fixed at 60 (`packages/domain/src/ranking.ts:1-8`, `packages/domain/src/rrf.ts:20-27`). The rank is 1-based within that one arm's own list. It is neither a global rank nor a score, which is what lets the fold combine arms whose scores are incomparable (`packages/domain/src/rrf.ts:9-17`). `k` damps the difference between the top ranks, so one arm's confident first place cannot dominate four other arms' consensus (`packages/domain/src/rrf.ts:23-25`).

Contributions are summed per path, and a duplicate path inside one arm's list accumulates, matching the SQL's `SUM` over a `UNION ALL` (`packages/domain/src/rrf.ts:29-51`). A zero-weight arm is skipped entirely, so it is absent from the fold rather than adding a neutral term that later arithmetic could mistake for a real score (`packages/domain/src/ranking.ts:19-30`, `packages/domain/src/rrf.ts:46-47`). The fused list sorts by score descending with ties broken on path ascending, so the ordering is total and two runs over the same corpus produce the same list (`packages/domain/src/rrf.ts:53-63`).

MMR then reorders greedily by `lambda * relevance - (1 - lambda) * maxSimilarityToSelected`, with lambda at 0.5 (`packages/domain/src/ranking.ts:10-11`, `packages/domain/src/mmr.ts:20-71`). At `lambda >= 1` the function short-circuits and returns the input order truncated, because the penalty term is multiplied by zero and the greedy pass would otherwise burn quadratic cosine work to reproduce the order it was given (`packages/domain/src/mmr.ts:23-27`). A candidate with no vector takes penalty 0, which is the correct reading of unknown similarity, since a vectorless candidate cannot be shown to duplicate anything (`packages/domain/src/mmr.ts:28-32`).

### The merge divergence veto

Two memories above cosine 0.92 are treated as the same content and merged, keeping the older file (`packages/domain/src/merge.ts:21-22`). Orientation is arithmetic over corpus order: `activeCorpus` reads oldest-first, so the older path is the keeper by construction, and inside a model-proposed group the keeper is the member with the lowest corpus offset (`packages/sleep/src/phases/dedup-merge.ts:65-70`). The batched model arm hands `mergeOutcomes` an admit floor of 0 rather than the 0.92 threshold, because admission on that arm was already decided by the model's partition or by the phase's own filter, and re-gating on similarity would silently drop the frame-seeded pairs that carry the floor as their synthetic similarity (`packages/sleep/src/phases/dedup-merge.ts:192-206`). The veto exists because cosine similarity is geometric, and embedding models are weakest on the tokens that carry a fact's polarity and its discriminators. "The deploy step is safe" and "the deploy step is NOT safe" sit above 0.92, as do "retry 3 times" against "retry 13 times" and "M1" against "M1 Pro" (`packages/domain/src/merge.ts:1-13`). Because the merge keeps the older file, a merge that trusted cosine alone would fold a newer correction into an older wrong memory and restore the error the correction was written to fix.

The veto takes two `MergeText` values, each a `{gist, body}` pair: the memory's one-line `<mark>` claim and its whole article text (`packages/domain/src/merge.ts:44-50`). It is the disjunction of three deterministic predicates, and each predicate reads its own text (`packages/domain/src/merge.ts:207-218`, `:220-225`):

1. **Negation divergence** reads the joined text, gist and body together: exactly one side carries a negation marker (`packages/domain/src/merge.ts:164-172`, `:211-214`). The marker set holds 22 words (`packages/domain/src/merge.ts:72-96`), and contractions are expanded before tokenizing so "isn't" surfaces the underlying "not" (`packages/domain/src/merge.ts:98-121`).
2. **Numeric-token divergence** reads the gist alone: the two claims carry different numeric tokens (`packages/domain/src/merge.ts:174-185`, `:215`). Two gists with no numbers at all, or identical numbers, do not trip it. The gist rather than the article, because a body is where a memory cites its evidence, a date, a ticket id, an exit code, a cosine, and two honest tellings of one fact almost never cite the same numbers: a numeric set-equality over the whole article vetoed 349 of 349 candidates over two consecutive runs. A number in the claim is the fact itself, and "retry 3" against "retry 13" is two claims (`packages/domain/src/merge.ts:27-36`).
3. **Variant-qualifier divergence** reads the joined text: the two carry different version or variant qualifiers from a nine-word set (`packages/domain/src/merge.ts:123-137`, `:186-195`, `:216`).

A vetoed pair becomes a candidate contradiction for the conflict phase rather than a merge, however high its cosine runs (`packages/domain/src/merge.ts:10-13`). The guards are a post-filter over every proposal, a model's included: a model that groups a claim with its own negation is refused by the same predicate that refuses a blind cosine, so the set of pairs that can be committed does not widen when a model is bound (`packages/domain/src/merge.ts:14-19`). Under the dedup-merge phase a vetoed pair also becomes a review task, one per pair, naming the predicate that fired, minted in the same commit as the folds (`packages/sleep/src/phases/dedup-merge.ts:106-114`, `:674`).

`mergeOutcomes` classifies every oriented candidate pair into one of six stages, and `stageOf` tests them in this order: the per-cycle cap of 100 committed pairs, the strict similarity threshold, the divergence veto when both texts are present, a self-merge check, and the in-batch role guard; a pair that clears all five is `committed` (`packages/domain/src/merge.ts:236-242`, `:280-295`). The cap is tested first, so once 100 pairs have committed every later pair is counted as `cap` rather than as a veto. `mergeCandidates` is the `committed` subset of `mergeOutcomes`, in input order, as decisions (`packages/domain/src/merge.ts:313-324`). The outcome form exists so a caller can count refusals by cause: a phase that reported `candidates - decisions` as vetoed told an operator that a predicate fired on pairs no predicate had seen, which is how two all-refusing runs read as a divergence problem when half of them were role-guard skips (`packages/domain/src/merge.ts:239-242`). The in-batch role guard does the most work of the five. Every committed decision fixes its drop path as dropped and its keep path as kept for the rest of the batch, and three later uses are refused: a path already dropped cannot be dropped again, or two keepers would each believe they absorbed it; a path already dropped cannot become a keeper, or content would be folded into a file this same batch archives; and a path already a keeper cannot later be dropped. Given `(gf, a)` then `(b, gf)`, both would commit, `gf` absorbs `a` and is then archived into `b`, so `a`'s content is superseded into a file that no longer exists, and that is the loss the guard exists to prevent (`packages/domain/src/merge.ts:244-253`, `:291-293`). A path already a keeper may keep again: `(k, a)` then `(k, b)` is one page absorbing two duplicates in one batch, and nothing on that chain is archived twice or archived after being folded into. The earlier rule claimed both roles of a committed pair, which made a model group of N members fold at most one of them per run and reported the other N-2 as vetoes; the guard's job is the two corruptions above, and the fold budget belongs to the cap (`packages/domain/src/merge.ts:255-260`). Fixing roles rather than memberships keeps the output a function of input order alone: the first decision claiming a path in a role wins, matching the SQL result-set iteration upstream, and a later pair contradicting it is skipped rather than reordering anything (`packages/domain/src/merge.ts:262-264`).

### The frame key

The frame key gives the write path's conflict assist a cheap deterministic signal about whether two claims occupy the same slot. A frame is a subject plus a relation up to the last linking token, and the value is what follows. "The capital of India is New Delhi" keys on `the capital of india is` and carries `New Delhi` as the value, so a later claim writing a different value into the same slot is recognizable as a claim about the same thing without an LLM, without an embedding, and without reading the other claim (`packages/domain/src/frame.ts:1-8`).

The regex quantifier is greedy. The sentence matches the frame through `is` rather than stopping at the inner `of`, so the key is the longest frame the sentence states (`packages/domain/src/frame.ts:39-48`). A lazy quantifier would key that sentence on `the capital of` and collide it with every "the capital of" claim regardless of country.

Two guards apply, and both fail closed to `null`. They are asymmetric because the costs are asymmetric. A false frame collision claims two unrelated facts occupy one slot, while a missed collision leaves both facts stored, which is the existing behavior (`packages/domain/src/frame.ts:23-37`). The frame must be at least 3 tokens, so "Water is wet" and "Water is life" never share a key (`packages/domain/src/frame.ts:50-51`). The value must be 1 to 6 tokens, so a frame trailed by a clause is not read as a slot assignment (`packages/domain/src/frame.ts:53-54`).

A measurement in an external eval harness fixes the tokens, both thresholds, the greedy match, and the normalization. Tuning them in this file alone would leave the eval and the system disagreeing about what a conflict is (`packages/domain/src/frame.ts:9-21`).

### Recall disclosure under a character budget

A recall pack spends a character budget across full quotes and index lines. Arcs get 9000 characters and ordinary memories 16000, because an arc is a synthesis of many memories (`packages/index/src/disclosure.ts:19-23`, `:77-79`).

Three tiers map onto the HTML structure rather than onto a truncation of prose (`packages/index/src/disclosure.ts:1-17`). Tier 1 is the `<mark>` gist, always disclosed. Tier 2 is `<summary>` text, disclosed inside a full quote. Tier 3 is the `<details>` body, which reaches an agent only through `memory_read` and never through recall, because it is "how this was learned" material and spending a shared budget on it starves the claims of memories the agent has not seen yet. `<aside>` text is never quoted in an index line, because an aside is a scope caveat and presenting it as the memory would present the exception as the rule.

The fold walks candidates in rank order, and that order is authoritative. A candidate is never promoted past a better-ranked one to make it fit (`packages/index/src/disclosure.ts:81-91`). A candidate that does not fit becomes an index line and the fold continues, so a later shorter candidate can still be quoted. Without that, one long memory in the middle of the list would silently truncate every shorter one after it. A per-entity cap of 2 full quotes applies to entity names rather than to paths, which makes recall breadth-first over entities. Twelve memories about one service are twelve paths and would otherwise fill the budget with one entity's history (`packages/index/src/disclosure.ts:25-32`). Entity names are deduplicated per candidate, because a single memory can claim one name under two types and counting both would let it exhaust the cap by itself (`packages/index/src/disclosure.ts:111-119`).

## Policy and gates

- **Single write path:** every mutation to the managed tree goes through the store, so the endpoint-class rules and the render gate cannot be bypassed by a second caller. Enforced by construction: the store is the only module that writes memory files, and the CLI and MCP both reach the corpus through it. `packages/store/src/store.ts:1248-1254`.
- **Render gate:** rendered bytes are checked against every format constraint before they are written, staged, or committed, so a refusal leaves the tree byte-identical. Enforced in `renderChecked`, called by every write and every correction. `packages/store/src/store.ts:644-668`.
- **Dedupe before write:** the content-hash question is asked before any file is created, so a duplicate leaves no file, no stage, and no commit for the next `git status` to report. `packages/store/src/store.ts:715-729`.
- **Batch dedupe order:** a batch consults its own accepted hashes first and the store's index second, because the index does not yet know what this batch wrote. `packages/store/src/store.ts:810-844`.
- **Task dedupe exemption:** two open tasks with identical bodies are legitimately distinct work items, so the uniqueness rule excludes tasks on both sides: the partial index and the write path's lookup. `packages/index/migrations/0008_tasks.sql:119-127`.
- **Archive, never delete:** eviction, expiry, correction, and task completion all move a file to `archive/<YYYY>/<original-path>` with archive stamps applied. Nothing in the system deletes a memory, so a wrongly evicted memory is recoverable by reading the archive. `packages/sleep/src/phases/retention-triage.ts:9-17`, `packages/store/src/store.ts:564-598`.
- **Clean tree required:** `preflight` and any operation gated on `requireCleanTree` refuse when the managed tree has uncommitted changes. `packages/sleep/src/phases/preflight.ts:54`, `packages/store/src/store.ts:1354-1358`.
- **Task and memory graphs do not mix:** a memory-class rel with a task endpoint is refused, and a task-class rel requires both endpoints to be tasks, because a `blocks` edge reaching PageRank would let an agent's to-do list reweight the retention of its knowledge. Enforced in the store, because SQL can pair a rel with a class but cannot pair a class with the type of the files at either end. `packages/store/src/store.ts:1248-1296`.
- **Tasks default-excluded from search:** an unscoped query sees every type except `task`, and naming `task` in the type list opts a query in. A corpus with fifty open to-do items would otherwise put fifty of them in front of every recall. `packages/index/src/scope.ts:122-131`, `:262-280`.
- **An explicit type list is honored verbatim:** filtering `task` back out of a caller's own list would make the opt-in unreachable. The exclusion is a default that a caller can override. The rules that cannot be overridden are `edge_class` and the trace tables, and both refuse a call rather than quietly applying a default. `packages/index/src/scope.ts:266-272`.
- **Tasks skipped by every sleep phase:** a task is excluded from confidence decay, arc synthesis, retention triage, compress, reprieve, dedup-merge, edge typing, relationship mining, and placement triage. The retention score is dominated by recency and access, so a task nobody has touched for a month scores at the floor, which is exactly the task most likely to still be owed. `packages/sleep/src/sql.ts:34-41`, `packages/sleep/src/phases/retention-triage.ts:24-28`.
- **Arcs are never evicted and never expire:** an arc is a synthesis whose members may all have aged out, so scoring it on its own recency would discard the conclusion precisely when the evidence behind it faded. Arc demotion belongs to arc synthesis, which has the utility signal. `packages/sleep/src/phases/retention-triage.ts:19-22`, `packages/sleep/src/phases/reprieve.ts:24-26`.
- **Arcs are system-written:** `arc` is in the storage vocabulary and absent from the writable set, so an agent cannot assert a conclusion the corpus has not earned. `packages/contracts/src/types.ts:6-9`, `:34-40`.
- **Sleep is absent from the MCP surface:** a sleep run rewrites confidence across the corpus, archives memories, and creates a branch a human is expected to read, so it is an operator's action, launched as a run, rather than something an agent fires mid-conversation. `memhtml sleep run` is the only entry point. `apps/mcp/src/tools.ts:30-34`.
- **Per-tool dependency declarations:** each MCP tool declares only the services it uses, which keeps `memory_search` provably unable to reach the store and write. `apps/mcp/src/tools.ts:107-130`.
- **Every MCP tool declares a failure schema:** a tool with no declared failure gets `Schema.Never`, so the server rewrites every failure, typed domain errors included, to a generic internal-error string before it reaches the caller. `apps/mcp/src/tools.ts:47-55`.
- **Pre-merge quality gate:** a sleep branch cannot fast-forward `main` when the caller's gate fails. The discrimination eval is wired here, so a sleep run that degrades retrieval quality cannot land. `packages/sleep/src/review.ts:206-214`, `:319-331`.
- **Absent gate means no gate, by declaration:** the sleep package cannot import the eval without depending on it, so composition belongs to the CLI and a missing gate is visible in the caller's own wiring rather than silently supplied. `packages/sleep/src/review.ts:210-212`.
- **Main-advanced refusal:** a merge refuses when `main` has moved past the run's base sha and the advance touches at least one path the branch wrote, or when either diff cannot be read, because the run curated a corpus that may no longer exist; the refusal names the overlap. The operator reruns the sleep, which is cheap because every phase is idempotent. `packages/sleep/src/review.ts:211-259`.
- **Fast-forward on an unmoved `main`, a merge commit on a provably disjoint advance:** an unmoved `main` still fast-forwards with no merge commit, a disjoint advance lands as a merge commit that preserves both sides, and a conflict, unreachable if disjointness held, is aborted and refused rather than left in progress, so the conflict resolution is never a human editing generated `sitemap.xml` by hand. `packages/sleep/src/review.ts:233-239`, `:333-335`.
- **Discrimination gate is per-probe and absolute:** a single target ranked at or below any of its own controls is an inversion, and one inversion fails the run regardless of what MRR says, because an aggregate can be bought by thirty easy probes covering one broken one. `packages/eval/src/discriminate.ts:8-22`, `:218`.
- **MRR floor 0.85:** a gate below this admits a target losing to one of its own negation-flipped twins on one probe in seven. `packages/eval/src/discriminate.ts:99-104`.
- **An empty eval suite fails:** zero probes yields `mrr: 0`, which is below any floor, so a corpus whose probe generation silently produced nothing refuses rather than reporting a green gate over no measurement. `packages/eval/src/discriminate.ts:190-197`, `:218`.
- **Corpus MRR is reported and not gated:** it is dominated by corpus size rather than by ranking quality, so a gate on it would be a gate on how big the fixture is. `packages/eval/src/discriminate.ts:79-88`.
- **Phase failure is soft by default:** a failing phase is recorded `failed` and later phases still run, keeping every prior commit on the branch. The predecessor system ran thirteen phases in one transaction and lost four consecutive runs of curation to a single raise. `packages/sleep/src/contract.ts:72-106`.
- **Two hard prerequisites, and `preflight` is the broad one:** `preflight` is a declared prerequisite of every one of the sixteen phases after it, so a failed preflight commits nothing. Its four failures — a dirty tree, an `EmbedModelMismatch`, an `IndexStale` index, a `VectorCoverageLow` vector plane — each make every later commit wrong rather than merely unhelpful, and all four end in a corrupt run with a green report, which is the one outcome per-phase isolation is no defense against. `dedup-merge` is the second, gating `compress` and `retention-triage`, because both operate on the post-merge set. The pairs are spelled one literal at a time so the generated phase table can parse the array. `HARD_PREREQUISITES`, `packages/sleep/src/contract.ts:107-126`.
- **Two phases cannot commit:** `preflight` produces no mutation to review, and `relationship-mining` writes derived edges to the index only, because they are a re-derivable function of the corpus and the embedder and committing thousands would bury every real diff in machine noise. The list names phases that CANNOT commit, not phases that happened not to: `trace-consolidation` and `task-detection` are absent because each lands its output as its own reviewable commit, and each still reports `commitSha: null` on a run with nothing to write. `NON_COMMITTING_PHASES`, `packages/sleep/src/contract.ts:241`, `packages/sleep/src/phases/relationship-mining.ts:6-19`.
- **Eight phases spend model calls; nine are deterministic:** `dedup-merge`, `entity-resolution`, `edge-typing`, `arc-synthesis`, `compress`, `trace-consolidation`, `task-detection`, and `placement-triage`. The list is DESCRIPTIVE and nothing branches on it — each phase reads `env.deps.model` itself and degrades on its own — so what it feeds is the generated phase table's `callsModel` column, and a phase omitted from it would still make its calls while being documented as deterministic. Membership means "spends calls when a model is bound", not "needs one to be useful": `dedup-merge` falls back to the 0.92 cosine floor plus the divergence veto and still commits, and `entity-resolution` runs its normalization and character-overlap passes either way. `LLM_PHASES`, `packages/sleep/src/contract.ts:168-177`.
- **A run's non-undoable state-plane writes are deferred to the merge:** `.memhtml/state.db` is not rebuildable from the tree, so a row written during a phase would outlive the branch that earned it and `git branch -D` would stop being a real abort — for the consolidation watermark that is content loss, since the watermark is an anti-join and the session it covers is never selected again. A phase records each such write as a JSONL line in `.memhtml/sleep/<run-id>.pending.jsonl`, committed on its own branch, and `merge` applies the ledger after the fast-forward succeeds, reporting `marksPending` beside `marksApplied`. Corroboration counters stay at phase time on purpose: `detections` counts runs on which a model read the corpus and proposed the merge, and a discarded run did both. `packages/sleep/src/contract.ts:360-373`, `packages/sleep/src/contract.ts:423`, `packages/sleep/src/contract.ts:496-497`, `packages/sleep/src/review.ts:351`.
- **A derived edge can never evict:** the retention `contested_status` signal counts only `derived = 0` file-borne edges, so an uncorroborated machine suspicion has no retention effect. `packages/contracts/src/edges.ts:122-128`, `packages/sleep/src/phases/relationship-mining.ts:10-13`.
- **A machine-found contradiction needs two detections:** only `rel: "contradicts"` above the confidence floor bumps the corroboration counter, and only two or more detections promote the edge into both files. A directional rel carries no such gate, because it carries no retention penalty and is cheap for a reviewer to delete. `packages/sleep/src/phases/edge-typing.ts:48-59`, `:140`.
- **Edge typing detects and stops:** a promoted `contradicts` asserts the conflict and nothing more — the phase never supersedes, closes a `memhtml-valid-until`, or archives either side, because choosing the winner of a contradiction is a one-way door on stored belief that belongs to an agent or a human. `packages/sleep/src/phases/edge-typing.ts:78-81`.
- **Per-batch model isolation:** each model call is wrapped so one malformed payload skips its BATCH and is counted, rather than failing the phase and discarding the work already done. A run that typed nine batches and lost the tenth has done nine batches of work. `packages/sleep/src/batch.ts:249-269`.
- **Entity auto-merge at 0.85, review band 0.75 to 0.85:** the band is counted and never merged, because entity merges are a one-way door on stored identity and the failure mode of an over-eager threshold is silent and permanent. `packages/sleep/src/phases/entity-resolution.ts:86-90`.
- **Character overlap is entity resolution's pre-pass, not its decision core:** a character ratio settles a separator or casing change with no model call, and is structurally blind to short-name-against-full-name — measured on the live corpus, `laith` against `laith al-saadoon` scores 0.476, below even the review band. `packages/sleep/src/phases/entity-resolution.ts:44-51`.
- **A memory centroid is evidence handed to the model, never a merge threshold:** two spellings of one person are written about in the same terms and two services in one domain also are, so under the deterministic embedder `checkout-api` against `payments-api` sits at 0.9333 while the one person's two spellings sit at 0.7788, and any cosine floor that merged the person would fuse the two services first. The rule is stated in the phase and the two figures are measured in its test. `packages/sleep/src/phases/entity-resolution.ts:57-60`, `packages/sleep/tests/llm-phases.test.ts:2511-2516`.
- **A model names an entity cluster; code names its canonical:** the surviving name is the one the most active files claim, ties broken lexicographically, because the canonical is every rewrite's target and becomes a person file's path. `packages/sleep/src/phases/entity-resolution.ts:499-535`.
- **An alias-backed entity merge applies at once; a model-only merge waits two runs:** a `memhtml-alias` in a person file is a human's or an authoritative directory's assertion of identity, while a model proposal with no external evidence is corroborated in `state.entity_corroboration` before it is written. `packages/sleep/src/phases/entity-resolution.ts:41-46`, `packages/index/state-migrations/S0002_entity_corroboration.sql`.
- **A compress member is archived only when the model names it:** an omitted member stays active, and `absorbedKeys: []` produces no archive and no commit, so refusing to fold is a valid model answer. `packages/sleep/src/phases/compress.ts:41-45`.
- **A new arc's slug is minted from the title, never by the model:** a model-chosen slug is a model-chosen file path, which is a path-traversal surface and a collision surface at once. `packages/sleep/src/phases/arc-synthesis.ts:35-37`.
- **Reinforcement cooldown 900 seconds:** `access_count` feeds the salience retrieval arm, so without a cooldown replaying one query ten times would inflate that memory's salience tenfold and let a loop in an agent rewrite the corpus's ranking. `packages/domain/src/reinforce.ts:10-19`, `packages/domain/src/ranking.ts:13-17`.
- **Embed-model mismatch is a hard refusal:** a half-migrated vector space degrades every cosine while every individual vector stays well-formed, so the check runs before any write and before the first write records a watermark. `memhtml index rebuild --embed` is the one path allowed past the guard, and so the only path that rewrites vectors: a rebuild empties `embeddings` with the other memory tables and records the configured model before any vector is written, so it migrates the whole space rather than mixing two. The model is named by `MEMHTML_AWS_REGION` and the pinned watermark rather than by a flag — there is no `--embed-model`, because the destination space is configuration and not a per-call argument. `packages/index/src/indexer.ts:324-338`, `:393-412`, `apps/cli/src/errors.ts:176`.
- **An interrupted rebuild is detectable, and detectable as its own state:** a rebuild clears `index_state.head_sha` in the same transaction as its truncate and writes the commit back only after every projection landed, so an EXISTING row with a NULL `head_sha` is exactly a rebuild that died inside that window — a different state from no row at all, which is a store nothing has indexed yet and which `update` answers with a full rebuild. Here the tables are half-empty with no watermark to diff from, so a diff would report `unchanged: true` over rows the tree still holds. `update` raises `IndexStale` → `ERR_INDEX_STALE`, whose one suggestion is `memhtml index rebuild`: `index update` is what raises the tag, so suggesting it would send the operator in a circle, and a rebuild is the only call that repopulates the tables the interrupted pass left partial. `packages/index/src/indexer.ts:167-184`, `:842-846`, `apps/cli/src/errors.ts:177-180`.
- **`EmbedModelMismatch` travels out of preflight rather than being swallowed:** continuing would corrupt dedup, mining, and edge typing while reporting green. `packages/sleep/src/phases/preflight.ts:16-22`.
- **Missing Bedrock credentials degrade, `MEMHTML_EMBED=off` disables:** an absent credential degrades one search at call time to the lexical floor, while `off` degrades every search, and an operator reading the manifest needs those to be different states. `apps/cli/src/config.ts:129-134`.
- **`MEMHTML_LLM=off` reports its effect on a credential-free sleep run:** of the eight phases in `LLM_PHASES`, the six with nothing to do without a model report `no model bound` and stay `ok` rather than red, while `dedup-merge` and `entity-resolution` fall back to their deterministic passes and still commit. `placement-triage` reports a reason on a run without `--deep` either way, since it spends calls only under that flag. `apps/cli/src/config.ts:141-146`, `packages/sleep/src/contract.ts:168-177`, `packages/sleep/src/phases/edge-typing.ts:259-261`.
- **Entity extraction is on by default, like the embedder:** `MEMHTML_EXTRACT_ENTITIES=off` (or `MEMHTML_LLM=off`) removes the one model call per write batch that changes what the write stores, so extracted entities land in files as if authored. The write never waits on or fails with the model; a failed extraction is a logged warning and an unextracted batch. `apps/cli/src/config.ts:147-157`.
- **A dangling href is rewritten when the target was archived and dropped with a warning otherwise:** an archived target still exists and the edge still says something true, while a target that is gone means the edge asserts a relationship to nothing. `packages/sleep/src/phases/integrity.ts:20-29`.
- **Generated artifacts are regenerated only by the integrity phase and by `memhtml publish`, never on an ordinary write:** they are the design's one merge-conflict source, and a deterministic regeneration plus `merge=ours` resolves a conflict without a human reading XML. `packages/sleep/src/phases/integrity.ts:31-34`.
- **`memhtml doctor --fix` repairs exactly two of ten findings:** dangling hrefs and orphan state rows are settleable without a judgement call; an inbox memory, a vocabulary warning, a stale index, an overdue task, a stale blocker, a task inbox, an untyped entity reference, a stuck sleep run, and low vector coverage all need a human or an agent to decide, so doctor names the command rather than running it behind the operator's back. `apps/cli/src/doctor.ts:86-101`.
- **A repair counts only when its bytes reached disk:** a file whose write failed is reported under `repaired.failedWrites`, counted under neither `rewritten` nor `dropped`, and never staged — staging the unchanged file would put the pre-repair bytes into a commit whose subject claims they were repaired, and counting it would report a finding as settled while it is still open. `apps/cli/src/doctor.ts:258`, `:578-592`.
- **The trace scan's four file counters partition, and `sessionsWritten` does not:** `skipped + tailed + rescanned + filesFailed` is every file the scan planned to read, so a read failure stays visible in the total instead of shrinking it. `sessionsWritten` counts the files for which a `traces` ROW was actually written, which is a different question — a file read successfully but yielding no session id is tailed and unwritten. `packages/traces/src/scan.ts:65`, `apps/cli/src/operations.ts:2468-2501`.
- **Doctor is the only surface that reads `due_at`:** a task is default-excluded from search and skipped by every sleep phase, so nothing else in the system will ever mention that a deadline passed. `apps/cli/src/doctor.ts:52-54`.
- **Inbox depth thresholds 20 memories and 10 tasks:** the two crowds mean different things. An unplaced memory is a placement rule that stopped matching what agents write; an unplaced task is work with no project, and a task inbox is meant to be drained rather than accumulated. `apps/cli/src/doctor.ts:104-117`.
- **Cost guards per sleep cycle:** merge decisions capped at 100 pairs and dedup at 300 components a run in batches of 40, edge-typing candidates capped at 200 in batches of 30 with at most 50 promotions, mined pairs capped at 2000, compress candidates capped at 2000 in batches of 8, arc evidence capped at 40 memories. `packages/domain/src/merge.ts:22-25`, `packages/sleep/src/phases/dedup-merge.ts:169`, `:178`, `packages/sleep/src/phases/edge-typing.ts:114`, `:127`, `:150`, `packages/sleep/src/phases/relationship-mining.ts:55-60`, `packages/sleep/src/phases/compress.ts:94`, `:103`, `packages/sleep/src/phases/arc-synthesis.ts:39-40`. With a model bound, dedup mines at the 0.86 component floor up to 800 pairs a run, truncates a component past 8 members to its lowest paths, and hands `mergeOutcomes` an admit floor of 0. `packages/sleep/src/phases/dedup-merge.ts:130`, `:142`, `:158`, `:206`.
- **Bounded embed concurrency at 6:** every caller on the deployment draws on the same Bedrock token's tokens-per-minute quota, so an unbounded fan-out would spend the whole store's budget in one burst and throttle every other consumer. `packages/llm/src/constants.ts:13-27`.
- **Write batch 500 rows:** one batch is one transaction, so the bound caps how much work a single failure discards and how long one write holds the WAL write lock against a concurrent reader. `packages/index/src/schema-const.ts:77-85`.
- **Confidence commit delta 0.005:** confidence decay is the widest commit in a sleep run, one meta line across many files, so a sub-threshold delta is dropped rather than committed, keeping the run's diff reviewable. `packages/domain/src/decay.ts:141-150`.
- **The trace index stores no session content:** only pointers and capped heads, 500 characters for a session's first prompt and 200 per prompt. `packages/traces/src/extract.ts:47-51`, `apps/mcp/src/tools.ts:979`.
- **`MEMHTML_TRACE_ROOT` is read-only and never written.** `apps/cli/src/config.ts:78-83`.
- **Error codes and response types are append-only, and agents branch on the code:** once shipped a code's meaning never changes and a code is never removed, while the human `error` string changes freely as wording improves. `apps/cli/src/envelope.ts:8-11`, `:76-116`.
- **`--dense` drops nulls and indentation:** an agent pasting CLI output into a prompt spends tokens on content rather than decoration. `apps/cli/src/envelope.ts:172-189`.
- **`MEMHTML_REFUSE_ENV_ROOT` closes the environment as a door to a repo:** with it set, `MEMHTML_ROOT` and the `~/memhtml` default are not read, and a call that opens a repo without `--repo` is `ERR_REPO_REQUIRED` at exit 2, decided before any service is built so nothing is opened. It exists for a test suite calling the CLI in-process and for an agent runtime that exports `MEMHTML_ROOT` to every subprocess it starts: issue #144 was a help mutant that rebuilt a live index exactly that way. `ERR_REPO_REQUIRED` rather than `ERR_MISSING_ARGUMENT`, because the flag is optional on every command and a caller needs to learn one fact, that this environment wants `--repo`. `apps/cli/src/run.ts:1052-1090`, `apps/cli/src/envelope.ts:88-90`.
- **The switch fails closed:** only absent, blank, `0`, `false`, `no`, and `off` leave it off, compared case-insensitively after trimming; a spelling it does not know, `y` or `enabled`, turns it on rather than silently off, the inverse of how `MEMHTML_EMBED` reads its one opt-out. It is read from `process.env` directly rather than through `effect/Config`, because the answer is needed before any Effect runs. `apps/cli/src/config.ts:44-60`.
- **`serve mcp` and `exec` resolve the root themselves:** one supervises a child over it and the other mounts a worktree of it, so for those two an injected layer is not a door to the root and under the refusal only `--repo` counts. Commands that never open a repo, `manifest`, `help`, `agents-doc`, `eval discriminate`, are unaffected. `apps/cli/src/run.ts:1045-1050`, `apps/cli/src/config.ts:73-76`.
- **`apply` and `exec` read a bare `-` positional as stdin:** `surplusArgs` exempts the dash for those two commands only, because both declare no positional and both document `-` as the spelling that reads the stream from a pipe; their own mutual-exclusion checks refuse a dash beside a real `--file`. `apps/cli/src/run.ts:1006-1014`, `:1028-1032`.
- **Prompt caching is off by default on the OpenAI sleep lane:** the dialect sends `prompt_cache_options: {mode: "explicit"}` with no breakpoints, which Bedrock documents as no prompt caching and no cache-write charge. Bedrock's implicit mode writes the whole prompt to the cache at 1.25x the input rate on every call that clears the 1,024-token minimum, and the eight sleep system prompts are 189 to 496 tokens, so the only prefix that could be reused never reaches the minimum and the only prefix that does, system plus a unique batch, is never seen twice; the access log showed every call paying the write premium with `cached_tokens: 0`. `packages/llm/src/wire.ts:48-79`.
- **`MEMHTML_OPENAI_PROMPT_CACHE` takes two values:** `off` and `implicit`, compared case-insensitively after trimming; unset or blank is `off`, and any other value throws at startup naming the variable, because a typo that fell back silently would put the write premium back on every call while the environment claimed to have turned it off. `implicit` is for an OpenAI-compatible endpoint that rejects the Bedrock-only field. `packages/llm/src/wire.ts:69-98`.
- **`ModelClientDefaults` are per-deployment wire defaults, and a field set on the call wins:** the sleep phases say what a call is, system, effort, budget; the environment says how the transport carries it; the two meet in `makeModelClient`, where `options.openaiPromptCache ?? defaults.openaiPromptCache` resolves the one default that exists today. `packages/llm/src/model-client.ts:73-81`, `:140-162`.
- **Published JSON Schemas are closed:** the model tool schema and the consolidator's contract both derive their JSON Schema with `Schema.toJsonSchemaDocument(schema, { onExcessProperty: "error" })`, so an undeclared key is a decode failure rather than a silently dropped field. `packages/llm/src/structured.ts:44-45`, `apps/consolidator/src/contract.ts:737-738`.
- **Five transport variables route model calls:** `MEMHTML_LLM_BASE_URL` names an OpenAI- and Anthropic-compatible proxy origin, and a set-but-malformed value fails at startup rather than falling back to the direct path; `MEMHTML_LLM_API_KEY` is the proxy's bearer token, read only when the base URL is set; `MEMHTML_LLM_MODEL_PREFIX` defaults to `bedrock/` and `none` disables it; `MEMHTML_LLM_MODEL_MAP` names single models by exact `from=to` pairs, sent verbatim without the prefix; `MEMHTML_OPENAI_PROMPT_CACHE` is read on the direct path and the proxy path alike. `apps/cli/src/config.ts:95-128`.
- **A failed run puts `HEAD` back:** when a sleep run fails, the runner checks out the branch the run started from and reads the current branch back to prove it landed; the run branch keeps its commits for review. A detached start has no branch to return to and a refused checkout is a warning, never a guess at `main`, because guessing would move a checkout the operator put somewhere on purpose. `packages/sleep/src/run.ts:478-509`.
- **A second eval arm gates the write path:** the write-path gate is composed from the production functions in the order the fleet runs them, `door:schema`, `door:grounding`, `door:quote`, `phase:refusal`, with `accepted` as the fifth outcome, and none of the four is re-implemented in the eval. The phase's refusal is deliberately redundant with the door, so a consolidator that skipped the door still does not get past the phase. `packages/eval/src/write-path-gate.ts:10-44`.
- **Write-path F1 floor 0.88:** the measured baseline F1 is 0.9333 and the floor is that minus five points, floored to two decimals. Five points and not zero, because the floor is the alarm for a class-sized regression and the frozen manifest under `packages/eval/fixtures/` is the alarm for a one-item one; a floor pinned at the baseline would fire on every deliberate corpus edit and train the reader to refreeze without looking. `packages/eval/src/write-path-run.ts:39-52`.
- **`candidateRefusalFor` is exported for the eval, not for a second caller:** the sleep phase's per-candidate gate is exported so the write-path eval scores the production function itself; the phase calls it and nothing else in the package does. Its trailing-punctuation strip is a character scan rather than `/[.!?]+$/`, because that regex is polynomial on a claim that is mostly punctuation and the claim is a value an injected collaborator supplies. `packages/sleep/src/phases/trace-consolidation.ts:756-765`, `:788-795`.

### Host integrations (`@memhtml/integrations`)

`@memhtml/integrations` wires a coding agent host to a store: it renders the host's MCP entry, hooks, instruction block, and skill, and lands them as one file transaction per host. It is pure rendering and file transactions; nothing in it opens the store or runs retrieval (`packages/integrations/src/index.ts:1-13`).

- **Two closed vocabularies, read from one place:** `HOSTS` is `claude`, `codex`, `cursor`, `opencode`, and `HOOK_EVENTS` is the host-neutral `session-start`, `user-prompt-submit`, `pre-compact`, `session-end`; each host's installer maps those onto the host's own event names and the hook engine maps the host's stdin payload back. Every module and both CLI commands import the lists rather than restating them, so a host added in `HOSTS` is one the parser, the manifest, the doctor, and the smoke census learn about at once. `packages/integrations/src/types.ts:1-14`, `:20-34`.
- **`HOOK_MODES` decides which hooks install writes:** `all`, `session`, or `none`, and `all` is the default. `packages/integrations/src/types.ts:36-38`, `apps/cli/src/commands.ts:1140-1141`.
- **Ownership is per write kind:** a `file` is wholly ours and its SHA-256 is the receipt's claim; a `fragment` lives inside a file other tools also own, a JSON key, a TOML fence, a Markdown block, a hooks array entry, and only the fragment's rendered bytes are claimed, under one of six `MANAGED_ROLES`: `mcp-entry`, `hooks`, `instruction-block`, `skill`, `plugin`, `rules`. `packages/integrations/src/types.ts:78-100`.
- **A human's edit wins:** before anything is written, every receipt claim is re-hashed against disk and every unclaimed artifact is checked for something already sitting where ours goes; either refuses the whole install with `IntegrationModified` and writes nothing. `packages/integrations/src/install.ts:14-17`, `:683-690`.
- **`--force` is the only override, and it keeps the prior bytes:** the previous content is written beside the file as `<path>.memhtml-backup-<stamp>`, with a filename-safe ISO instant, and the report names the backup. `packages/integrations/src/install.ts:16-17`, `:661-664`.
- **Install is all-or-nothing:** every target file is snapshotted, the writes land one file at a time, and the receipt is written last, so a receipt on disk always describes files that exist; any throw restores every snapshot and removes every backup, leaving a failed install indistinguishable from one that never ran. `packages/integrations/src/install.ts:19-22`.
- **A plan is pure:** each artifact carries `apply`, `strip`, and `ownedNow` as total functions of the file's current text, and nothing in a plan touches disk, so `--dry-run` is the real install's code path minus its last step and reports byte for byte what a real one would write. `packages/integrations/src/install.ts:7-12`.
- **The install order is the contract:** validate the root, refuse a symlinked path, re-hash the receipt, refuse an artifact we do not own, and only then snapshot, write, and record. `packages/integrations/src/install.ts:666-678`.
- **Uninstall has no `--force`:** the receipt is the only license to delete, every entry is re-hashed first, and one drifted entry refuses the whole uninstall, because overwriting an edit is recoverable from a backup and deleting a file somebody has made their own is not. `packages/integrations/src/uninstall.ts:1-7`.
- **Nothing is inferred from a config file:** an MCP entry or a hook that resembles ours but that no receipt names is left alone; only an entry we wrote licenses a delete. `packages/integrations/src/uninstall.ts:9-11`.
- **Uninstall removes only its own directories:** `skills/memhtml` and `.memhtml-integrations` go when empty; `~/.claude` and `~/.cursor` are the host's, and an empty one stays because the host created it and may be about to write to it. `packages/integrations/src/uninstall.ts:43-50`.
- **`IntegrationModified` names the difference, never the contents:** it carries `host`, `path`, and a `detail` that is a hash, a missing entry, or an unmanaged sibling entry. Install refuses on it without `--force` and uninstall refuses always. `packages/integrations/src/errors.ts:3-15`.
- **Install with no host wires every host whose home directory exists:** `~/.claude`, `~/.codex`, `~/.cursor`, `~/.config/opencode`, each a directory the host creates itself on first run and never as a side effect of something else. `packages/integrations/src/hosts.ts:116-127`.
- **Transcript indexing hooks are Claude Code only:** `@memhtml/traces` reads Claude Code's JSONL format and no other, so a host with a `null` trace root installs no indexing hook rather than one with nothing to read; `MEMHTML_TRACE_ROOT` lets an operator who knows better say so for any host. `packages/integrations/src/hosts.ts:129-141`.
- **Claude Code project scope follows `AGENTS.md`:** a repository that already has one gets the instruction block there plus an `@AGENTS.md` import in `CLAUDE.md`, one copy of the prose visible to both, and the transaction layer decides by looking at disk because which file exists is not a property of the host. `packages/integrations/src/hosts.ts:74-78`.
- **The binary triple is resolved once and recorded:** the node executable, the `memhtml` entry script, the `memhtml-mcp` entry script, and the version, because every command line in every host's config is derived from it, and `integrations doctor` comparing what resolves today against the receipt is what tells an upgrade from a move. The resolver refuses a build that produced one bin and not the other. `packages/integrations/src/locate.ts:1-13`, `packages/integrations/src/types.ts:45-54`.
- **Absolute binary paths by default:** an installed config records `process.execPath` plus the resolved entry script, because GUI hosts do not inherit a shell PATH and a moved toolchain alias has orphaned a bare command before; `--bare-command` writes `memhtml` and `memhtml-mcp` and leaves PATH to the operator. `packages/integrations/src/types.ts:40-44`, `apps/cli/src/commands.ts:1143-1148`.
- **Doctor reads, never scaffolds:** the store-root row reads the directory for `.memhtml/` and never calls `memhtml status`, because `status` on a bare directory scaffolds a store and a diagnostic that creates what it checks always passes. `packages/integrations/src/doctor.ts:10-12`.
- **Codex hook trust is informational with `ok: true`:** trust is keyed to a hook's hash inside the host and nothing outside it can read the decision, so a red row for something unknowable would train an operator to ignore the report. `packages/integrations/src/doctor.ts:12-15`.
- **Every path install writes is checked for symlink components:** the walk stops at the first component that does not exist, and an existing component that is a symlink refuses, because an installer must never follow a link into a place it did not intend to write; a `~/.claude` linked into a dotfiles repo would turn a config edit into a commit in someone else's tree. `packages/integrations/src/fs.ts:155-163`, `packages/integrations/src/install.ts:678`.
- **`integrations shell --write` is the one symlink exception:** a `~/.zshrc` symlinked into a dotfiles repository is the normal setup rather than the hazard, and the operator named that file instead of it being derived from a host's config. `apps/cli/src/integrations.ts:460-470`.
- **`--project` resolves to the git top level:** the host files a project install writes are read from the root, so the path given is resolved with `git rev-parse --show-toplevel`, and not-a-repository, the filesystem root, and `$HOME` are each refused with `ERR_INVALID_FLAG` at exit 2, because what is unusable is the value on the command line. `apps/cli/src/integrations.ts:162-193`.
- **Each host is its own transaction, planned first:** with several hosts a refusal on the third would leave the first two wired, so every host is planned in dry-run form before any real pass, which turns partly applied into nothing written; what remains is a disk failure during the real pass, and the report names the hosts that did land. `apps/cli/src/integrations.ts:297-304`.
- **The rc-file PATH line is guarded:** the shell snippet wraps its PATH export in a `case` on `:$PATH:` rather than appending unconditionally, because an rc file is sourced once per shell and a nested shell would otherwise accumulate the same directory over and over. `packages/integrations/src/shell.ts:26-30`.
- **The recall discipline is stated once:** five paragraphs in `@memhtml/contracts`, recall, read, cite, reinforce, write, in the order an agent meets them; the guide topic, the instruction block, the skill, and the retrieval tool descriptions render that one list. `packages/contracts/src/guidance.ts:17-45`.

### The `memhtml hook` engine

`memhtml hook <event> --host <host>` is what an installed host hook runs. The engine lives in `apps/cli` and calls the dialect renderers from `@memhtml/integrations` to speak each host's protocol; the engine produces text and knows nothing about JSON envelopes or which host reads which stream (`packages/integrations/src/index.ts:4-6`, `apps/cli/src/hook.ts:35-38`).

- **It never fails:** a hook runs inside a host's turn, so a failure here would be a failure of the developer's session rather than of `memhtml`; every path funnels through `runHook`, whose error channel is `never`, and a storage failure, a defect, a missing plane, and a blown deadline all become the empty string at exit 0, which every host reads as "nothing to add". There is deliberately no way to tell those apart from a quiet store, because a hook has no channel in which to report one. `apps/cli/src/hook.ts:24-28`, `:323-333`.
- **It is bounded, and the bound is on the turn:** a recall event gets 1500 ms and an indexing event 10 000 ms, applied to the whole engine rather than to one query; expiry answers the empty string, so a slow store degrades to no injection rather than to a slow session. The indexing bound is longer because nothing waits on it, and still finite because a host that kills the process would lose the whole scan. `apps/cli/src/hook.ts:30-33`, `:79-87`.
- **Two events index, two inject:** `pre-compact` and `session-end` index transcripts and produce no output, ever; `user-prompt-submit` searches on the prompt and injects the hits; `session-start` recalls on the working directory and appends the open task queue. `apps/cli/src/hook.ts:70-71`, `:225-252`.
- **Defaults 5 hits and 3000 characters:** `--limit` defaults to 5 hits on a per-prompt recall and `--budget` to a 3000-character session-start pack, and `commands.ts` states the same values as the flags' documented defaults. `apps/cli/src/hook.ts:73-77`.
- **A gist is cut to 240 characters and a pack lists at most 5 open tasks:** the cut is so one memory can never dominate an injected block, and open work means `todo` and `doing`. `apps/cli/src/hook.ts:89-96`.
- **The dialect is asked first:** whether this host reads anything on this event is answered by `renderHookOutput` returning the empty string on a probe, before the store is touched, so a host that cannot inject spends no part of the turn on a query whose result it would discard. `apps/cli/src/hook.ts:219-223`.
- **A hook never scaffolds a store:** building the app layer on a missing root would create a memory repo that nothing else ever reads, so `.git` is probed at the root, a file for a worktree as well as a directory, and a missing store prints nothing at exit 0. `apps/cli/src/hook.ts:335-356`.
- **The open-task list is a separate indexed scan:** `SearchScope` excludes `task` from every unscoped query, so the working set arrives through the direct scan that exists for it, in two calls because `ListTasksParams.status` is scalar and open work is two statuses; a failing task scan leaves the memory pack intact and the tail absent. `apps/cli/src/hook.ts:234-252`.
- **The per-prompt header states three rules:** the hits are the ranker's guess and not a citation, `memory_read` is how a body is obtained, and `memory_reinforce` is how the guess becomes evidence, because salience only moves on a read or an outcome and a block that did not ask for those two calls would inject memories that can never learn from having been useful. `apps/cli/src/hook.ts:98-106`.
- **`hook.output` is the second envelope exception:** its success stdout is the host's hook protocol rather than the JSON envelope, as `help` on a terminal already is; its usage errors stay in the failure envelope, so the type still names the command in the manifest. `apps/cli/src/envelope.ts:48-57`.
- **Three error codes for the family:** `ERR_UNKNOWN_HOST` and `ERR_UNKNOWN_HOOK_EVENT` are usage errors at exit 2, since the fix is on the command line; `ERR_INTEGRATION_MODIFIED` is a runtime refusal at exit 1, a receipt-owned file or entry that no longer matches. All three are appended at the end of the list, because the list is append-only. `apps/cli/src/envelope.ts:107-114`.
- **Closed vocabularies arriving as positionals are refused before the app layer:** the hook event and the integrations host are checked in `run.ts` rather than in a dispatch arm, at exit 2 with the whole vocabulary enumerated as suggestions, because a refusal raised inside `dispatch` becomes exit 1 after a database was opened for a call that was never going to run; `memhtml hook nope --host claude` answers on a machine with no store. A closed-vocabulary flag needs no entry here, since `--host` declares its values and the flag check already refuses `--host nope`. `apps/cli/src/run.ts:1102-1143`.

### The dedup-merge model arm

With a model bound, `dedup-merge` mines candidate pairs at a lower floor, builds connected components over the union of near-duplicate edges and frame-key matches, and asks the model to partition each component into groups of memories that are the same memory. Everything the fold writes is derived afterwards, and every pair a group implies passes the same `mergeOutcomes` filter the deterministic path uses (`packages/sleep/src/phases/dedup-merge.ts:55-63`).

- **The model partitions; code chooses:** the model never chooses the canonical, never names a write target, and is never asked an n² pair question; a component of five is one entry in one batch's member list. `packages/sleep/src/phases/dedup-merge.ts:55-57`.
- **Component floor 0.86, below the merge floor:** a pair between 0.86 and 0.92 is one no cosine can settle, about one thing but not provably one claim, and that band is what a semantic reader is for. The floor is only a floor: a pair that clears it still has to survive the model's partition and then the veto, so more recall here cannot lower the bar on what gets written. `packages/sleep/src/phases/dedup-merge.ts:117-130`.
- **800 mined pairs a run:** `DEDUP_PAIR_LIMIT` is `MAX_MERGE_PAIRS * 8`, twice the deterministic path's `* 4`, because the floor moved down and the pair count grows with the band while the commit cap does not; the multiplier buys candidate coverage and cannot buy extra writes. `packages/sleep/src/phases/dedup-merge.ts:132-142`.
- **A component past 8 members is truncated to its lowest paths:** a fact restated eight times is already pathological, so a larger component is almost always the recall floor chaining distinct facts through shared vocabulary; truncation keeps the lowest paths rather than the highest cosines, so what is considered is a property of the corpus and not of the floor, and the remainder is deferred to a later run rather than lost. `packages/sleep/src/phases/dedup-merge.ts:144-158`.
- **The batched arm hands `mergeOutcomes` an admit floor of 0:** admission is already decided when the filter runs, and what remains is the veto, the self check, the role guard, and the cap; zero rather than 0.86 because the comparison is strict and a frame-seeded pair the corpus never mined carries the floor itself as its similarity. `packages/sleep/src/phases/dedup-merge.ts:192-206`.
- **Model groups first, mined pairs second:** the deterministic floor never regresses, because every pair the no-model path would have merged is still in the list, and where the two disagree the semantic answer wins the path, because the model read both files and the cosine read neither. `packages/sleep/src/phases/dedup-merge.ts:88-100`.
- **The older file is kept:** `activeCorpus` reads oldest-first, so the older path is the keeper by construction, and inside a model group the keeper is the member with the lowest corpus offset. `packages/sleep/src/phases/dedup-merge.ts:65-70`.
- **One commit for the whole batch:** a keeper's `memhtml-supersedes` points at its dropped file's archive path, which exists only after the commit lands, so splitting the batch would create a dangling href in the commit that made it dangle. `packages/sleep/src/phases/dedup-merge.ts:102-104`.
- **A vetoed pair becomes a review task:** `mintVetoTasks` opens one task per vetoed pair naming the predicate that fired, in the same commit as the folds, keyed on the two paths sorted so the arm that proposed the pair does not change which task it is; the sweep closes a pair whose veto stops firing, because the divergence was the finding and it is gone. `packages/sleep/src/phases/dedup-merge.ts:106-114`, `:668-669`, `:674-702`, `:754-758`.
- **Refusal counters partition by cause:** `vetoed`, `roleGuarded`, `capped`, and `unadmitted`, and `merged + vanished + those four` equals the candidate count, so a role-guard skip can no longer read as a divergence problem. `packages/sleep/src/phases/dedup-merge.ts:589-607`.
- **Without a model the phase is the deterministic floor, unchanged:** it mines at 0.92, orients, and hands the pairs to `mergeOutcomes`; a run with no credentials still folds every duplicate a cosine can prove, and every count it reports is what the phase reported before it could call a model. `packages/sleep/src/phases/dedup-merge.ts:83-86`.
