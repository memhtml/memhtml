# memhtml-public · Business logic

Describes the source at 0.16.0 (2026-10-18). Citations are `path:line` into that tree.

This file indexes the domain rules the codebase enforces and names the line that enforces each one. The rules govern memory management: what counts as a valid memory file, what a write may and may not do to the managed tree, how a session commit is judged and landed, how the head ranks a search, and which gates a curation run must clear before it lands.

**Scope.** In scope: application-layer validations, invariants, calculations, and policy gates in `packages/` and `apps/cli`, `apps/mcp`. The SQLite `CHECK` and uniqueness constraints in `packages/index/migrations/` are also in scope, because several of them are the only enforcement point for a rule the application relies on, and because the application's own predicates are written to agree with them. `docs/design.md` §15 to §24 states the reasoning behind the v2 rules at more length. Out of scope: the `apps/docs` Astro package, test fixtures, and build tooling.

**Removed in 0.16.** The sleep pipeline (`memhtml sleep`, `@memhtml/sleep`) and the consolidator (`apps/consolidator`) are gone, and so are the rules that belonged only to them. Sessions and the head carry the write path in their place, and `memhtml curate` carries curation. See [Migrate to 0.16](https://memhtml.github.io/learn/operations/migrate-to-0-16/).

**Two facts a reader needs before reading a rule.** First, this repository stores no memories. It's the software that manages a separate directory, the `memhtml root`, located by `MEMHTML_ROOT` (`apps/cli/src/config.ts:108-117`). Every rule below acts on whatever root the environment points the binary at. The root's git tree is the system of record. `.memhtml/index.db`, the head's snapshots, and the vector caches inside the root are rebuildable projections of it. Second, a coding agent is the primary consumer of these surfaces. The rules are shaped for that consumer. The CLI answers in a versioned JSON envelope with a stable error code an agent branches on (`apps/cli/src/envelope.ts:105-161`), the MCP server publishes a JSON Schema per tool, and the format constraints are stated in tool descriptions so an agent learns a rule before it spends a round trip discovering it (`apps/mcp/src/tools.ts:136-173`).

**Violations are collected rather than short-circuited.** `checkDocument` runs every check and concatenates the results, so one parse tells an author everything wrong with the file rather than the first thing (`packages/html/src/constraints.ts:426-437`). Violations join into a single `InvalidMemory.reason` with `"; "` (`packages/html/src/constraints.ts:41-42`). Nothing in the checker throws and nothing repairs a violation, because a checker that silently fixed one would make `memhtml doctor` report a clean corpus that the next hand-edit breaks again (`packages/html/src/constraints.ts:37-39`). `validateOps` follows the same rule over a batch. It walks every op and returns every violation, except the batch cap, which answers alone (`packages/session/src/validate.ts:209-217`).

**Constraints 1 through 5 refuse; constraint 6 warns.** A file using an element outside the closed vocabulary still indexes, because the format has to degrade gracefully on a file a human hand-wrote in a hurry (`packages/html/src/constraints.ts:30-39`). Warnings are deduplicated by element name, so a file with forty stray `<div>` elements produces one actionable line (`packages/html/src/constraints.ts:381-391`).

**The six violation kinds.** A session commit's checks are mechanical. No model call and no I/O run, and every check reads the head view and the ops, so a refusal costs nothing and leaves the tree untouched (`packages/session/src/validate.ts:29-32`). The kinds are `format`, `duplicate`, `claim-edit`, `reserved-path`, `batch-cap`, and `write-bar` (`packages/session/src/validate.ts:34-52`). The batch keeps running state as it walks. Edges and entities are tracked as the batch has left them, so a batch may drop an edge it added earlier and may not drop one twice. Archive and move destinations are tracked so one slot is never written twice. Every path the batch creates is gathered before the walk, so a link may name a target the batch archives later in the order (`packages/session/src/validate.ts:221-288`).

**What depends on the hash invariant.** Access bookkeeping, a session's `link`, `unlink`, `label`, `unlabel`, `archive` and `move` ops, and every `doctor --fix` repair write to the head or relocate a file. First, the digest is taken over `<article>` text only, and the article is located first so head content can never reach it (`packages/html/src/hash.ts:151-161`). Second, every head edit goes through byte-splicing editors rather than a parse-and-serialize round trip, which would drop a `<pre>` newline per write (`apps/cli/src/repair.ts:16-19`). The session validator then reads the invariant back. An archive or a move whose article hash differs from the source's is refused, so a relocated record is provably the same record (`packages/session/src/validate.ts:365-374`, `:485-491`).

### Reciprocal rank fusion and MMR

Each v1 retrieval arm produces its own ranked candidate list and contributes `weight / (rank + k)` per hit, with `k` fixed at 60 (`packages/domain/src/ranking.ts:1-8`, `packages/domain/src/rrf.ts:20-27`). The rank is 1-based within that one arm's own list. It's neither a global rank nor a score, which is what lets the fold combine arms whose scores are incomparable (`packages/domain/src/rrf.ts:9-17`). `k` damps the difference between the top ranks, so one arm's confident first place can't dominate four other arms' consensus (`packages/domain/src/rrf.ts:23-25`).

Contributions are summed per path, and a duplicate path inside one arm's list accumulates, matching the SQL's `SUM` over a `UNION ALL` (`packages/domain/src/rrf.ts:29-51`). A zero-weight arm is skipped entirely, so it's absent from the fold rather than adding a neutral term that later arithmetic could mistake for a real score (`packages/domain/src/ranking.ts:26-37`, `packages/domain/src/rrf.ts:46-47`). The fused list sorts by score descending with ties broken on path ascending, so the ordering is total and two runs over the same corpus produce the same list (`packages/domain/src/rrf.ts:53-63`).

MMR then reorders greedily by `lambda * relevance - (1 - lambda) * maxSimilarityToSelected`, with lambda at 0.5 (`packages/domain/src/ranking.ts:17-18`, `packages/domain/src/mmr.ts:20-71`). At `lambda >= 1` the function short-circuits and returns the input order truncated, because the penalty term is multiplied by zero and the greedy pass would otherwise burn quadratic cosine work to reproduce the order it was given (`packages/domain/src/mmr.ts:23-27`). A candidate with no vector takes penalty 0, which is the correct reading of unknown similarity, since a vectorless candidate can't be shown to duplicate anything (`packages/domain/src/mmr.ts:28-32`). The v1 index applies MMR after its polarity step (`packages/index/src/retrieval.ts:539`).

### The divergence predicates

Cosine similarity is geometric, and embedding models are weakest on the tokens that carry a fact's polarity and its discriminators. "The deploy step is safe" and "the deploy step is NOT safe" sit above 0.92, as do "retry 3 times" against "retry 13 times" and "M1" against "M1 Pro" (`packages/domain/src/merge.ts:1-13`). Three deterministic predicates name those three ways two near-identical texts can state different facts:

1. **Negation divergence**: exactly one side carries a negation marker (`packages/domain/src/merge.ts:164-172`). The marker set holds 22 words (`packages/domain/src/merge.ts:72-96`), and contractions are expanded before tokenizing so "isn't" surfaces the underlying "not" (`packages/domain/src/merge.ts:98-121`).
2. **Numeric-token divergence**: the two texts carry different numeric tokens (`packages/domain/src/merge.ts:174-185`). Two texts with no numbers at all, or identical numbers, don't trip it.
3. **Variant-qualifier divergence**: the two carry different version or variant qualifiers from a nine-word set (`packages/domain/src/merge.ts:123-137`, `:186-195`).

Two callers read them in 0.16. The v1 retrieval's polarity step demotes the negation-flipped twin of a better answer. A candidate is demoted only when three things hold at once: its text disagrees with the query's polarity, another candidate agrees with the query, and the two sit at cosine 0.9 or above. A lone negated memory with no affirmative near-copy stays where fusion put it (`packages/index/src/polarity.ts:3-26`, `:47-51`). The eval's control generator is the predicates read backwards. Each control is built to trip its own family's predicate against its target, and a control that only trips the disjunction is refused, because the numeric predicate could fire on an incidental digit and make a failed polarity flip look adversarial (`packages/eval/src/controls.ts:7-23`, `:133-145`).

### The frame key

The frame key gives the write path a cheap deterministic signal about whether two claims occupy the same slot. A frame is a subject plus a relation up to the last linking token, and the value is what follows. "The capital of India is New Delhi" keys on `the capital of india is` and carries `New Delhi` as the value, so a later claim writing a different value into the same slot is recognizable as a claim about the same thing without an LLM, without an embedding, and without reading the other claim (`packages/domain/src/frame.ts:1-8`). Three callers read it. The v1 batch write's conflict assist keys each op once (`apps/cli/src/operations.ts:534-545`). A session commit links a put to every other active record with its key (`packages/session/src/commit.ts:197`). The head stores the key on every record, and the curator's briefing and the collapse planner split each key's records by the value they write into it (`packages/head/src/record.ts:44`, `packages/curator/src/planner/plan.ts:148`).

The regex quantifier is greedy. The sentence matches the frame through `is` rather than stopping at the inner `of`, so the key is the longest frame the sentence states (`packages/domain/src/frame.ts:39-48`). A lazy quantifier would key that sentence on `the capital of` and collide it with every "the capital of" claim regardless of country.

Two guards apply, and both fail closed to `null`. They're asymmetric because the costs are asymmetric. A false frame collision claims two unrelated facts occupy one slot, while a missed collision leaves both facts stored, which is the existing behavior (`packages/domain/src/frame.ts:23-37`). The frame must be at least 3 tokens, so "Water is wet" and "Water is life" never share a key (`packages/domain/src/frame.ts:50-51`). The value must be 1 to 6 tokens, so a frame trailed by a clause isn't read as a slot assignment (`packages/domain/src/frame.ts:53-54`).

A measurement in an external eval harness fixes the tokens, both thresholds, the greedy match, and the normalization. Tuning them in this file alone would leave the eval and the system disagreeing about what a conflict is (`packages/domain/src/frame.ts:9-21`).

### Recall disclosure under a character budget

A recall pack spends a character budget across full quotes and index lines. Arcs get 9000 characters and ordinary memories 16000, because an arc is a synthesis of many memories (`packages/index/src/disclosure.ts:19-23`, `:77-79`).

Three tiers map onto the HTML structure rather than onto a truncation of prose (`packages/index/src/disclosure.ts:1-17`). Tier 1 is the `<mark>` gist, always disclosed. Tier 2 is `<summary>` text, disclosed inside a full quote. Tier 3 is the `<details>` body, which reaches an agent only through `memory_read` and never through recall, because it's "how this was learned" material and spending a shared budget on it starves the claims of memories the agent hasn't seen yet. `<aside>` text is never quoted in an index line, because an aside is a scope caveat and presenting it as the memory would present the exception as the rule.

The fold walks candidates in rank order, and that order is authoritative. A candidate is never promoted past a better-ranked one to make it fit (`packages/index/src/disclosure.ts:81-91`). A candidate that doesn't fit becomes an index line and the fold continues, so a later shorter candidate can still be quoted. Without that, one long memory in the middle of the list would silently truncate every shorter one after it. A per-entity cap of 2 full quotes applies to entity names rather than to paths, which makes recall breadth-first over entities. Twelve memories about one service are twelve paths and would otherwise fill the budget with one entity's history (`packages/index/src/disclosure.ts:25-32`). Entity names are deduplicated per candidate, because a single memory can claim one name under two types and counting both would let it exhaust the cap by itself (`packages/index/src/disclosure.ts:111-119`). Recall on the head folds with this same function (`apps/cli/src/head-retrieval.ts:169-172`, `:198-202`).

### Head search ranking

The head ranks one version of the corpus with a lexical arm and, when the caller passes vectors and a query vector, a vector arm. Both run over active records only (`packages/head/src/search.ts:9-12`). The lexical arm is BM25 over the title, the claim, and the body, read from the version's persistent lexical index. The vector arm orders the active records that have a vector by cosine, brute force (`packages/head/src/search.ts:14-17`).

- **Each arm is capped at 40.** BM25 scores every record that shares one token with the query, so an uncapped arm voted for hundreds of records, and each weak match collected RRF mass that a record found by meaning alone couldn't. The vector arm has the same cap for the same reason, since cosine gives every embedded record a score (`packages/head/src/search.ts:66-79`).
- **Equal scores share a rank.** Two records an arm can't tell apart, such as byte-identical articles under BM25, get the same rank and contribute the same RRF share, so they tie in the fused score (`packages/head/src/search.ts:91-110`).
- **Recency is a tie-break and never an arm.** It decides only between hits whose fused score is exactly equal, newest first, and path ascending decides after it. A byte-identical newer twin outranks the older copy, and a clearly better older match stays above a newer, weaker one (`packages/head/src/search.ts:20-25`, `:155-166`). A weighted recency arm was a second full ranking, and a curation landing that made the surviving records newer made older targets lose to weaker matches. Measured 2026-09-28 on a copy of a large store with the head gate's 200 title probes, seed 1, top 10, the tie-break rule raised MRR from about 0.56 to about 0.94 at the base (`packages/head/src/search.ts:27-40`).
- **A hit names its arms.** `arms` lists the arms that ranked it, plus `recency` when its fused score equals another candidate's, which is when recency or path decided its place (`packages/head/src/search.ts:46-54`).
- **The function never embeds.** The caller owns the vectors, keyed by content hash, and the query vector, so a search with neither is the lexical search exactly (`packages/head/src/search.ts:41-42`).

### The head gate

The gate asks whether the version being landed still finds what the base version found (`packages/head/src/gate.ts:9`). It's stated over two versions of one corpus and never over a fixture.

- **Probes** are a seeded sample of up to 200 records active in BOTH versions, each queried by its own title (`packages/head/src/gate.ts:11-14`, `:31-34`). A record the landing adds isn't probed, because it has no base rank to compare against. A record the landing archives leaves the probe set too, and the probe of the record it folded into measures whether the fold helped (`packages/head/src/gate.ts:14-18`).
- **Two inversion kinds** are counted at both versions. `fell-out` is a probe whose target isn't in the top 10. `superseded-outranks` is a record the target supersedes ranking above the target (`packages/head/src/gate.ts:20-22`).
- **The pass rule** is `mrr >= max(0, mrrBefore - 0.02)` and an inversion count that didn't grow (`packages/head/src/gate.ts:22-25`, `:214`). The tolerance exists because a landing that archives a near-duplicate reshuffles BM25's document frequencies by a hair.
- **A failure** is `HeadGateFailed` (`packages/head/src/gate.ts:264-270`), which the CLI answers as `ERR_DISCRIMINATION_FAILED` (`apps/cli/src/errors.ts:79-80`).

### Inbox placement

The curator's briefing computes a home for every inbox record, so the model files by evidence rather than by guess (`packages/curator/src/inbox.ts:30-48`).

- **A home** is `areas/<slug>/` or `resources/<tag>/` holding at least one active record. The inbox, `areas/arcs/`, `resources/people/`, and any directory a writer-bucket glob matches are never homes (`packages/curator/src/inbox.ts:32-36`, `isBucketHome`, `packages/curator/src/inbox.ts:155-156`).
- **A generic entity places nothing.** An entity carried by more than 20% of the active records, and never a floor below 10 records, is the store's subject rather than a record's (`packages/curator/src/inbox.ts:36-38`, `:124-129`).
- **A home is confident** when an entity names it or at least 2 of its records carry the record's entities, and it strictly outscores the runner-up. A tag match alone is evidence and never a home (`packages/curator/src/inbox.ts:315-318`).
- **A new home** opens under `resources/<entity name>/` when a `project`, `repo`, `service`, `system`, or `topic` entity is carried by at least 3 inbox records (`packages/curator/src/inbox.ts:131-139`, `:322-353`).
- **The list** quotes the quota plus a third, 20 homes at most, each claim cut at 200 characters (`packages/curator/src/inbox.ts:114-121`). Tasks, verdicts, and people records aren't placeable (`isPlaceable`, `packages/curator/src/inbox.ts:188-192`).

### The collapse planner's cuts

`curate collapse` plans its folds with no model call and no I/O. Four cuts run in order, each over the members the earlier cuts left (`packages/curator/src/planner/plan.ts:22-51`).

0. **Rulings**, when supplied. A path ruled `archive` or `trace` joins its partition's archive cluster, `fold` with a theme joins that theme's fold, and `keep` leaves every later cut. A ruling is a human's decision, so it also admits the records the charter otherwise shields, `resources/people/` and `task` rows (`packages/curator/src/planner/plan.ts:26-30`, `isShielded`, `packages/curator/src/planner/plan.ts:173-174`).
1. **Source plus memory type.** Source is the `memhtml-author` meta, `(none)` when absent (`packages/curator/src/planner/plan.ts:31-35`, `:53-69`).
2. **Frame key within a partition.** A frame-key group folds only when every member writes the same value or the same claim. Members with different values are contradiction candidates and become a `keep` cluster. Verdicts with different titles disagree even when their claims match (`packages/curator/src/planner/plan.ts:36-43`, `frameGroupAgrees`, `packages/curator/src/planner/plan.ts:160-170`).
3. **A kNN similarity graph plus an entity layer**, cut by Louvain. A community of two or more is a fold, and one larger than `maxFold` is `keep`, because one canonical can't carry it faithfully (`packages/curator/src/planner/plan.ts:44-46`).
4. **PageRank anchors** per cluster pick the canonical candidate and the title a fold is briefed under (`packages/curator/src/planner/plan.ts:47`).

The defaults are 10 neighbors, a cosine floor of 0.35, a large group at 30 members, `maxFold` 120, home default `areas`, and seed 42 (`packages/curator/src/planner/types.ts:117-124`). A fold over more than 30 members has the driver write the archives and links, an archive cluster runs 180 ops per session, and a fold session briefs at most 170 members (`packages/curator/src/planner/types.ts:108-115`).

## Policy and gates

- **Two write paths, one lock:** the v1 store writes a record with `git add` and `git commit`, and a session commit writes blobs, a tree, and a commit through plumbing, then moves the checkout and the ref. Both serialize on the repository's checkout lock, so neither can sweep the other's half-done state into its own commit. `packages/contracts/src/checkout-lock.ts:5-29`, `packages/store/src/store.ts:1442-1468`, `packages/session/src/commit.ts:399-404`.
- **Render gate:** rendered bytes are checked against every format constraint before they're written, staged, or committed, so a refusal leaves the tree byte-identical. Enforced in `renderChecked`, called by every write and every correction. `packages/store/src/store.ts:698-722`.
- **Dedupe before write:** the content-hash question is asked before any file is created, so a duplicate leaves no file, no stage, and no commit for the next `git status` to report. `packages/store/src/store.ts:769-783`.
- **Batch dedupe order:** a batch consults its own accepted hashes first and the store's index second, because the index doesn't yet know what this batch wrote. `packages/store/src/store.ts:864-898`.
- **Task dedupe exemption:** two open tasks with identical bodies are legitimately distinct work items, so the uniqueness rule excludes tasks on both sides: the partial index and the write path's lookup. `packages/index/migrations/0008_tasks.sql:119-127`.
- **Archive, never delete:** correction, task completion, and a session's `archive` op all move a file to `archive/<YYYY>/<original-path>` with archive stamps applied. Nothing in the system deletes a memory, so a wrongly archived memory is recoverable by reading the archive. `packages/store/src/store.ts:612-652`, `packages/session/src/commit.ts:104-111`.
- **A landing refuses a dirty touched path:** when `HEAD` is the ref, uncommitted state at a path the landing changes is `worktree-dirty` and nothing moves; uncommitted edits at other paths survive the two-tree merge. `packages/session/src/commit.ts:273-276`, `:308-311`.
- **Task and memory graphs don't mix:** a memory-class rel with a task endpoint is refused, and a task-class rel requires both endpoints to be tasks, because task topology is working state and shouldn't reweight the knowledge graph. Enforced in the store, because SQL can pair a rel with a class but can't pair a class with the type of the files at either end. `packages/store/src/store.ts:1308-1356`.
- **Tasks default-excluded from search:** an unscoped query sees every type except `task`, and naming `task` in the type list opts a query in. A corpus with fifty open to-do items would otherwise put fifty of them in front of every recall. `packages/index/src/scope.ts:122-131`, `:262-280`.
- **An explicit type list is honored verbatim:** filtering `task` back out of a caller's own list would make the opt-in unreachable. The exclusion is a default that a caller can override. The rules that can't be overridden are `edge_class` and the trace tables, and both refuse a call rather than quietly applying a default. `packages/index/src/scope.ts:266-272`.
- **Arcs are curation's to write:** `arc` is in the storage vocabulary and absent from the writable set, and `areas/arcs/` is a reserved path outside the `curate` scope, so an agent can't assert a conclusion the corpus hasn't earned. `packages/contracts/src/types.ts:34-40`, `packages/session/src/validate.ts:57-63`, `:85-86`.
- **Curation is absent from the MCP surface:** a curator archives memories and creates a branch a human is expected to read, so it's an operator's action rather than something an agent fires mid-conversation. `apps/mcp/src/tools.ts:31-35`.
- **Per-tool dependency declarations:** each MCP tool declares only the services it uses, which keeps `memory_search` provably unable to reach the store and write. `apps/mcp/src/tools.ts:107-124`.
- **Every MCP tool declares a failure schema:** a tool with no declared failure gets `Schema.Never`, so the server rewrites every failure, typed domain errors included, to a generic internal-error string before it reaches the caller. `apps/mcp/src/tools.ts:47-55`.
- **Discrimination gate is per-probe and absolute:** a single target ranked at or below any of its own controls is an inversion, and one inversion fails the run regardless of what MRR says, because an aggregate can be bought by thirty easy probes covering one broken one. `packages/eval/src/discriminate.ts:8-22`, `:218`.
- **MRR floor 0.85:** a gate below this admits a target losing to one of its own negation-flipped twins on one probe in seven. `packages/eval/src/discriminate.ts:99-104`.
- **An empty eval suite fails:** zero probes yields `mrr: 0`, which is below any floor, so a corpus whose probe generation silently produced nothing refuses rather than reporting a green gate over no measurement. `packages/eval/src/discriminate.ts:190-197`, `:218`.
- **Corpus MRR is reported and not gated:** it's dominated by corpus size rather than by ranking quality, so a gate on it would be a gate on how big the fixture is. `packages/eval/src/discriminate.ts:79-88`.
- **Reinforcement cooldown 900 seconds:** `access_count` feeds the salience retrieval arm, so without a cooldown replaying one query ten times would inflate that memory's salience tenfold and let a loop in an agent rewrite the corpus's ranking. The cooldown has one call site, and SQL and `shouldBumpAccess` share one window constant. `packages/domain/src/reinforce.ts:10-19`, `packages/domain/src/ranking.ts:20-24`, `packages/index/src/reinforce.ts:8-18`.
- **Embed-model mismatch is a hard refusal:** a half-migrated vector space degrades every cosine while every individual vector stays well-formed, so the check runs before any write and before the first write records a watermark. `memhtml index rebuild --embed` is the one path allowed past the guard, and so the only path that rewrites vectors. A rebuild empties `embeddings` with the other memory tables and records the configured model before any vector is written, so it migrates the whole space rather than mixing two. The model is named by `MEMHTML_AWS_REGION` and the pinned watermark. There's no `--embed-model`, because the destination space is configuration and never a per-call argument. `packages/index/src/indexer.ts:324-338`, `:393-412`, `apps/cli/src/errors.ts:216`.
- **An interrupted rebuild is detectable as its own state:** a rebuild clears `index_state.head_sha` in the same transaction as its truncate and writes the commit back only after every projection landed, so an EXISTING row with a NULL `head_sha` is exactly a rebuild that died inside that window. That's a different state from no row at all, which is a store nothing has indexed yet and which `update` answers with a full rebuild. Here the tables are half-empty with no watermark to diff from, so a diff would report `unchanged: true` over rows the tree still holds. `update` raises `IndexStale` as `ERR_INDEX_STALE`, whose one suggestion is `memhtml index rebuild`. `index update` is what raises the tag, so suggesting it would send the operator in a circle. `packages/index/src/indexer.ts:167-184`, `:842-846`, `apps/cli/src/errors.ts:217-220`.
- **Missing Bedrock credentials degrade, `MEMHTML_EMBED=off` disables:** an absent credential degrades one search at call time to the lexical floor, while `off` degrades every search, and an operator reading the manifest needs those to be different states. `apps/cli/src/config.ts:193-197`.
- **`MEMHTML_LLM=off` removes every model call:** the write-time entity extractor is unbound and a batch writes exactly what it was given, so a run with no credential still succeeds. `apps/cli/src/config.ts:236-240`.
- **Entity extraction is on by default, like the embedder:** `MEMHTML_EXTRACT_ENTITIES=off` (or `MEMHTML_LLM=off`) removes the one model call per write batch that changes what the write stores, so extracted entities land in files as if authored. The write never waits on or fails with the model; a failed extraction is a logged warning and an unextracted batch. `apps/cli/src/config.ts:242-251`.
- **A dangling href is relinked to its archived form when one exists and dropped otherwise:** `archivedFormOf` takes the latest of the path's archive slots over ten years, the latest year and then that year's highest generation, so the most recent archiving of a path wins even when a lower slot is missing from the index. Only authored edges are repaired, since an index-only edge is fixed by the next rebuild. `apps/cli/src/repair.ts:54-101`, `:111-126`.
- **Generated artifacts are regenerated only by `memhtml publish`:** they're `merge=ours`, so a conflict is resolved by regenerating, which only works when regeneration is deterministic. `apps/cli/src/artifacts.ts:7-20`.
- **`memhtml doctor --fix` repairs exactly two of eleven findings:** dangling hrefs and orphan state rows are settleable without a judgement call; an inbox memory, a vocabulary warning, a stale index, an overdue task, a stale blocker, a task inbox, an untyped entity reference, low vector coverage, and a nested archive path all need a human or an agent to decide, so doctor names the command rather than running it unasked. `apps/cli/src/doctor.ts:84-100`.
- **A repair counts only when its bytes reached disk:** a file whose write failed is reported under `repaired.failedWrites`, counted under neither `rewritten` nor `dropped`, and never staged. Staging the unchanged file would put the pre-repair bytes into a commit whose subject claims they were repaired, and counting it would report a finding as settled while it's still open. `apps/cli/src/doctor.ts:227`, `:501-515`.
- **The trace scan's four file counters partition, and `sessionsWritten` doesn't:** `skipped + tailed + rescanned + filesFailed` is every file the scan planned to read, so a read failure stays visible in the total instead of shrinking it. `sessionsWritten` counts the files for which a `traces` ROW was actually written, which is a different question. A file read successfully but yielding no session id is tailed and unwritten. `packages/traces/src/scan.ts:65`, `apps/cli/src/operations.ts:2343-2376`.
- **Doctor is the only surface that reads `due_at`:** a task is default-excluded from search, so nothing else in the system will ever mention that a deadline passed. `apps/cli/src/doctor.ts:50-52`.
- **Inbox depth thresholds 20 memories and 10 tasks:** the two crowds mean different things. An unplaced memory is a placement rule that stopped matching what agents write; an unplaced task is work with no project, and a task inbox is meant to be drained rather than accumulated. `apps/cli/src/doctor.ts:95-105`.
- **Bounded embed concurrency at 6:** every caller on the deployment draws on the same Bedrock token's tokens-per-minute quota, so an unbounded fan-out would spend the whole store's budget in one burst and throttle every other consumer. `packages/llm/src/constants.ts:13-27`.
- **Write batch 500 rows:** one batch is one transaction, so the bound caps how much work a single failure discards and how long one write holds the WAL write lock against a concurrent reader. `packages/index/src/schema-const.ts:79-87`.
- **The trace index stores no session content:** only pointers and capped heads, 500 characters for a session's first prompt and 200 per prompt. `packages/traces/src/extract.ts:47-51`, `apps/mcp/src/tools.ts:963`.
- **`MEMHTML_TRACE_ROOT` is read-only and never written.** `apps/cli/src/config.ts:136-140`.
- **Error codes and response types are append-only, and agents branch on the code:** once shipped a code's meaning never changes and a code is never removed, while the human `error` string changes freely as wording improves. `apps/cli/src/envelope.ts:8-11`, `:105-161`.
- **`--dense` drops nulls and indentation:** an agent pasting CLI output into a prompt spends tokens on content rather than decoration. `apps/cli/src/envelope.ts:218-235`.
- **`MEMHTML_REFUSE_ENV_ROOT` closes the environment as a door to a repo:** with it set, `MEMHTML_ROOT` and the `~/memhtml` default aren't read, and a call that opens a repo without `--repo` is `ERR_REPO_REQUIRED` at exit 2, decided before any service is built so nothing is opened. It exists for a test suite calling the CLI in-process and for an agent runtime that exports `MEMHTML_ROOT` to every subprocess it starts: issue #144 was a help mutant that rebuilt a live index exactly that way. `ERR_REPO_REQUIRED` rather than `ERR_MISSING_ARGUMENT`, because the flag is optional on every command and a caller needs to learn one fact, that this environment wants `--repo`. `apps/cli/src/run.ts:1246-1308`, `apps/cli/src/envelope.ts:118-120`.
- **The switch fails closed:** only absent, blank, `0`, `false`, `no`, and `off` leave it off, compared case-insensitively after trimming; a spelling it doesn't know, `y` or `enabled`, turns it on rather than silently off, the inverse of how `MEMHTML_EMBED` reads its one opt-out. It's read from `process.env` directly rather than through `effect/Config`, because the answer is needed before any Effect runs. `apps/cli/src/config.ts:65-81`.
- **Some arms resolve the root themselves:** `serve mcp` supervises a child over it, `exec` mounts a worktree of it, `config` reads its policy file, and every `session` and `head` arm reads the store directly. For those an injected layer isn't a door to the root, so under the refusal only `--repo` counts. Commands that never open a repo, `manifest`, `help`, `agents-doc`, `eval discriminate`, are unaffected. `apps/cli/src/run.ts:1216-1245`, `apps/cli/src/config.ts:123-126`.
- **Four commands read a bare `-` positional as stdin:** `apply`, `exec`, `session exec`, and `session put`. `surplusArgs` exempts the dash for those four only, because each declares no positional and documents `-` as the spelling that reads the stream from a pipe; their own mutual-exclusion checks refuse a dash beside a real `--file`. `apps/cli/src/run.ts:1172-1185`, `:1199-1203`.
- **Prompt caching is off by default on the OpenAI lane:** the dialect sends `prompt_cache_options: {mode: "explicit"}` with no breakpoints, which Bedrock documents as no prompt caching and no cache-write charge. Bedrock's implicit mode writes the whole prompt to the cache at 1.25x the input rate on every call that clears the 1,024-token minimum. On 2026-09-11 the access log showed every OpenAI-lane call paying that write premium with `cached_tokens: 0`. `packages/llm/src/wire.ts:48-67`, `apps/cli/src/config.ts:187-191`.
- **`MEMHTML_OPENAI_PROMPT_CACHE` takes two values:** `off` and `implicit`, compared case-insensitively after trimming; unset or blank is `off`, and any other value throws at startup naming the variable, because a typo that fell back silently would put the write premium back on every call while the environment claimed to have turned it off. `implicit` is for an OpenAI-compatible endpoint that rejects the Bedrock-only field. `packages/llm/src/wire.ts:69-98`.
- **`ModelClientDefaults` are per-deployment wire defaults, and a field set on the call wins:** the caller says what a call is, system, effort, budget; the environment says how the transport carries it; the two meet in `makeModelClient`, where `options.openaiPromptCache ?? defaults.openaiPromptCache` resolves the one default that exists today. `packages/llm/src/model-client.ts:73-81`, `:140-162`.
- **Published JSON Schemas are closed:** the model tool schema derives its JSON Schema with `Schema.toJsonSchemaDocument(schema, { onExcessProperty: "error" })`, so an undeclared key is a decode failure rather than a silently dropped field. `packages/llm/src/structured.ts:44-45`.
- **Five transport variables route model calls:** `MEMHTML_LLM_BASE_URL` names an OpenAI- and Anthropic-compatible proxy origin, and a set-but-malformed value fails at startup rather than falling back to the direct path; `MEMHTML_LLM_API_KEY` is the proxy's bearer token, read only when the base URL is set; `MEMHTML_LLM_MODEL_PREFIX` defaults to `bedrock/` and `none` disables it; `MEMHTML_LLM_MODEL_MAP` names single models by exact `from=to` pairs, sent verbatim without the prefix; `MEMHTML_OPENAI_PROMPT_CACHE` is read on the direct path and the proxy path alike. `MEMHTML_CURATOR_MODEL` sits among them and names the curator's default model: `fake`, `bedrock:<modelId>`, or `proxy:<model>`, with `proxy:<default model>` when only the base URL is set. `apps/cli/src/config.ts:152-192`.

### The v1 doors

The v1 doors that create a record are `write`, `apply`, `correct`, and `task add` on the CLI, and `memory_write`, `memory_write_batch`, and `memory_correct` on MCP. They commit straight to the store with no write bar, where a session is judged by it (`packages/contracts/src/store-config.ts:23-26`, `apps/cli/src/doors.ts:44-76`).

- **`closed-in-session` is the default:** a process whose environment carries `MEMHTML_SESSION` has a session held to the write bar, so its v1 doors are closed and its other processes' doors stay open. `packages/contracts/src/store-config.ts:28-31`, `apps/cli/src/store-config.ts:111-118`.
- **`closed` closes every process:** records go in through sessions only, and a refusal with no session set names that mode. `apps/cli/src/store-config.ts:117`, `apps/cli/src/envelope.ts:153-156`.
- **Reads and edits of existing records stay open in every mode:** `link`, `archive`, `task status`, and `reinforce` create no record. `packages/contracts/src/store-config.ts:34-35`.
- **Refused before anything opens:** when `run()` knows the store, the CLI refuses a closed door as a usage error at exit 2, with the session command that does the same job as the suggestion. With an injected layer and no `--repo`, the record arm's own `guardV1Door` answers inside the layer. `apps/cli/src/run.ts:990-1016`, `apps/cli/src/store-config.ts:125-133`.
- **MCP reads the variable from its own environment:** MCP has no per-call session binding, so a server an agent runtime starts inside a run is closed under `closed-in-session`, and a shared server started outside any run is open. `apps/cli/src/store-config.ts:100-109`, `apps/mcp/src/handlers.ts:369`, `:437`, `:689`.

### Sessions: commit order and the checkout lock

A session is a log of overlay ops on a base commit, kept at `.memhtml/sessions/<id>.json` and committed in one commit. The commit runs in a fixed order, and the whole call holds the session's lock (`packages/session/src/commit.ts:399-426`).

0. **Recovery.** A log carrying `pending` names a commit an earlier call built and may have landed before it was killed. Reachable from the ref, it answers `committed` with `recovered: true` and clears the log. Unreachable, the call undoes whatever checkout update it made with `read-tree -m -u pending <tip>`, drops `pending`, and continues (`packages/session/src/commit.ts:335-347`).
1. **`validateOps`** under the session's scope and the store's write bar. Any violation is `refused` and writes nothing (`packages/session/src/commit.ts:495-501`).
2. **The ref must be at the validated version.** A ref past the base is `rebase-needed`, with `overlapping` naming the path collisions (`packages/session/src/commit.ts:502-507`).
3. **Frame-key contradictions** are marked on the new file's head before hashing (`packages/session/src/commit.ts:176-179`).
4. **Blobs, tree, and commit object** are written through a temporary index (`packages/session/src/commit.ts:516`).
5. **`pending: commit`** is saved to the log before anything shared is touched (`packages/session/src/commit.ts:537`).
6. **`landOnRef`** under the checkout lock: the ref must still be at step 2's value, a dirty session path is `worktree-dirty`, the checkout follows, and the compare-and-swap lands it. A lost swap rolls the checkout back and is `rebase-needed` (`packages/session/src/commit.ts:540-566`).
7. **The log is saved** with its base moved to the commit, no ops, and no pending (`packages/session/src/commit.ts:571`).

- **The checkout lock's timing is shared:** the lock directory is `.memhtml/checkout.lock`; it goes stale after 10 s with no refresh, the holder refreshes it every 2 s, and a waiter gives up after 15 s with pauses from 10 ms doubling to 250 ms. A timeout is `StorageFailure` `checkout.locked`, and any other failure `checkout.lock`. `packages/contracts/src/checkout-lock.ts:35-66`.
- **The lock's filesystem half is injected:** the session and the store each acquire it with `proper-lockfile`, because the two packages can't import each other and must agree on the path, the timing, and the reentrancy key. `packages/contracts/src/checkout-lock.ts:23-29`, `:83-86`, `packages/session/src/checkout-lock.ts:19-41`, `packages/store/src/checkout-lock.ts:19-44`.
- **A locked checkout clears `pending`:** when the landing can't take the checkout lock, nothing moved, so the log forgets the commit it built. `packages/session/src/commit.ts:549-555`.
- **The session lock is fail-fast:** a held `.memhtml/sessions/<id>.lock` fails a second writer at once with `session.locked`, and it goes stale after 30 s. `packages/session/src/session.ts:67`, `:156-188`.
- **A run-bound session refuses `duplicate` and `claim-edit` at put time:** outside a run those two are reported and left to the caller, because a rebase can change the answer either way. Inside a run the session is committed for the agent once the run ends, and one such op in the log refused the whole commit. `apps/cli/src/v2.ts:347-367`.
- **`--drop-refused` drops what a refusal names:** every op that touches a path a violation names leaves the log, and the rest commits. A batch-cap violation names no path and drops nothing, so the refusal stands. The dropped ops are appended to `.memhtml/sessions/<id>.dropped.jsonl`. `apps/cli/src/v2.ts:1366-1405`.
- **A move or an archive takes its repoints with it:** `withRepoints` completes a batch's moves and archives with an `unlink` and a `link` per live edge to the old path, the link naming the destination or the archive slot, placed before the first move or archive. `session exec`, the curator's binder, `curate collapse`, and `curate merge` apply it as they build ops, and `session commit` and the curator's landing append what a written log lacks against the version they commit over (`missingRepoints`). `packages/session/src/moves.ts`.

### Session prune

`session prune` removes the session state a store accumulates and nothing reads again. Each item goes only when older than the cutoff (`packages/session/src/prune.ts:29-35`).

- **What goes:** `<id>.idx` files by mtime, refs under `refs/memhtml/sessions/` by the committer time of the commit each names, `<id>.lock` directories that are also stale, and `<id>.json` logs that hold zero ops. `packages/session/src/prune.ts:29-35`.
- **What never goes:** a log that holds ops is listed under `unlanded` with its op count, `pending`, and age, and kept. The `<id>.dropped.jsonl` trail is kept too. `packages/session/src/prune.ts:37-39`.
- **Every id is handled under its session lock:** an id whose lock is held is listed under `busy` and left alone, and what was read before the lock is read again under it. `--dry-run` takes no lock and removes nothing. `packages/session/src/prune.ts:41-46`.
- **A lock directory needs both ages:** its cutoff is the larger of `--older-than` and the session lock's 30 s stale time, so a live holder is never reclaimed. `packages/session/src/prune.ts:186`.
- **Duration forms:** `--older-than` goes through `ms`, so `7d`, `48h`, `90m`, `1.5h`, and `2 weeks` all parse. A bare number is refused, because `--older-than 7` read as seven milliseconds would prune every idle log. `apps/cli/src/v2.ts:1553-1575`.

### Snapshots and the vector cache

- **One snapshot per commit:** `.memhtml/snapshots/<sha>.arrow`, Arrow IPC in the file format, one row per record, with the sha and the format version in the schema metadata. `packages/snapshot/src/snapshot.ts:1-15`, `:49-61`, `:177-181`.
- **A missing format key reads as format 1:** the file was written before the key existed, in the layout format 1 describes. The fallback is fixed at "1", so a later format still refuses those files. `packages/snapshot/src/snapshot.ts:63-68`.
- **Every refusal names its step:** `snapshot.read.file`, `read.decode`, `read.format`, `read.sha`, `read.schema`, and `read.rows`. A missing file is `null` and isn't logged. `packages/snapshot/src/snapshot.ts:495-528`.
- **A read failure is left in place, and every other refusal is removed:** an unreadable file is a miss with a warning, and a file that decodes wrong or names another sha is removed, so the next load doesn't pay to read it again. `apps/cli/src/head-cache.ts:119-152`.
- **Four snapshots are kept:** a write prunes the directory to the newest `SNAPSHOTS_KEPT`, and staging files left by a dead writer are swept after an hour. Writes are atomic and skip `fsync`, because a load that can't read a snapshot reads git instead. `packages/snapshot/src/prune.ts:20`, `packages/snapshot/src/staging.ts:25`, `packages/snapshot/src/snapshot.ts:326-345`.
- **One vector cache per space:** `.memhtml/vectors/<model>@<dim>.arrow`, one row per content hash, ignored by git and rebuilt by `memhtml head embed`. `packages/snapshot/src/vectors.ts:1-9`, `:68`, `vectorCachePathFor`, `packages/snapshot/src/vectors.ts:87-92`.
- **The space lives in the metadata as well as the filename:** two model ids can sanitize to one filename, so a file whose metadata names another space is refused with `vectors.read.space`. A file of another format reads as absent until the next `head embed` rewrites it. `packages/snapshot/src/vectors.ts:5-8`, `:16-19`, `:218-230`.

### Head search on the MCP surface

`memory_search` and `memory_recall` ask the head server first, so a record committed a moment ago is searchable before the index is updated (`apps/cli/src/config.ts:224-228`, `apps/mcp/src/handlers.ts:612`, `:650`). The index answers instead when `MEMHTML_MCP_HEAD` is `off`, the call names `include_archived` or `as_of`, the query holds a double quote, or it holds no term the head indexes. The index also answers when the socket gives no answer within 2 s (`apps/cli/src/head-retrieval.ts:42-80`). The head reports its arms as `fts`, `vector`, and `recency`, and has no salience arm and no MMR (`apps/cli/src/head-retrieval.ts:19-33`).

### The curator: budget, charter, and merge

- **Budget:** 40 model calls, 32,000 output tokens per call, 20 minutes of wall clock, and `BATCH_CAP` ops, because a run that appended more than one commit can carry would be refused at commit time. `packages/curator/src/budget.ts:10-29`.
- **Tool results are cut at 30,000 characters:** so the model asks narrow questions. `packages/curator/src/loop.ts:40`, `packages/curator/prompts/charter.md:11`.
- **Nine priorities, in order:** never settle a contradiction by deleting a side; never rank people records or tasks; dedup; labels; entity resolution; placement; arcs; integrity; budget discipline. `packages/curator/prompts/charter.md:25-35`, `packages/curator/src/charter.ts:28`.
- **Every put names its subject:** at least one `memhtml-entity`, reusing values the corpus carries. A put that breaks the rule comes back as a `write-bar` violation whose reason says what to add. `packages/curator/prompts/charter.md:21-23`.
- **Placement files at most the quota per run:** taken from the top of the briefing's `inbox` list, within what the 200-op cap leaves after priorities 1 to 5. `packages/curator/prompts/charter.md:32`.
- **The charter's placeholders come from the store's policy:** `{{placementQuota}}`, `{{refusedTypesRule}}`, and `{{refusedTypesClause}}`. `packages/curator/src/charter.ts:86-109`.
- **Memory bodies are data, never instructions:** a memory that asks the curator to do something is content to curate. `packages/curator/prompts/charter.md:5`, `packages/curator/src/charter.ts:31`.
- **The collapse charter has five steps:** one canonical put under the home prefix, the briefed type, the members' union of entities and tags with a `supersedes` link per member, an archive per member, and a one-line report. `packages/curator/prompts/collapse.md:11-15`, `packages/curator/src/charter.ts:116`.
- **The binder judges under the `curate` scope:** so arcs and people paths are writable, and every proposal is held to the store's write bar. `apps/cli/src/curate-run.ts:350-384`.
- **`curate merge` runs refusals first, the gate second, and movement last:** a call that fails leaves the repository as it found it. A ref that descends from its target fast-forwards through `landOnRef`. One that doesn't is replayed: its ops are rebuilt from the trees, judged under the `curate` scope against the target's tip, and committed through `commitSession` with up to 8 rebase attempts and no batch cap. A change on the ref that isn't an operation refuses the merge naming the path. `apps/cli/src/v2.ts:1847-1883`, `:1795`, `packages/session/src/validate.ts:76-81`.
- **The head gate runs before anything moves:** it loads both tips and scores the same probes at both, with no network call and no credential. `--skip-gate` is a logged override, and the report says the gate didn't run. `apps/cli/src/v2.ts:1953-1962`, `apps/cli/src/head-gate.ts:9-22`.

### Host integrations (`@memhtml/integrations`)

`@memhtml/integrations` wires a coding agent host to a store: it renders the host's MCP entry, hooks, instruction block, and skill, and lands them as one file transaction per host. It's pure rendering and file transactions; nothing in it opens the store or runs retrieval (`packages/integrations/src/index.ts:1-13`).

- **Two closed vocabularies, read from one place:** `HOSTS` is `claude`, `codex`, `cursor`, `opencode`, and `HOOK_EVENTS` is the host-neutral `session-start`, `user-prompt-submit`, `pre-compact`, `session-end`; each host's installer maps those onto the host's own event names and the hook engine maps the host's stdin payload back. Every module and both CLI commands import the lists rather than restating them, so a host added in `HOSTS` is one the parser, the manifest, the doctor, and the smoke census learn about at once. `packages/integrations/src/types.ts:1-14`, `:20-34`.
- **`HOOK_MODES` decides which hooks install writes:** `all`, `session`, or `none`, and `all` is the default. `packages/integrations/src/types.ts:36-38`, `apps/cli/src/commands.ts:1067-1068`.
- **Ownership is per write kind:** a `file` is wholly ours and its SHA-256 is the receipt's claim; a `fragment` lives inside a file other tools also own, a JSON key, a TOML fence, a Markdown block, a hooks array entry, and only the fragment's rendered bytes are claimed, under one of six `MANAGED_ROLES`: `mcp-entry`, `hooks`, `instruction-block`, `skill`, `plugin`, `rules`. `packages/integrations/src/types.ts:78-100`.
- **A human's edit wins:** before anything is written, every receipt claim is re-hashed against disk and every unclaimed artifact is checked for something already sitting where ours goes; either refuses the whole install with `IntegrationModified` and writes nothing. `packages/integrations/src/install.ts:14-17`, `:683-690`.
- **`--force` is the only override, and it keeps the prior bytes:** the previous content is written beside the file as `<path>.memhtml-backup-<stamp>`, with a filename-safe ISO instant, and the report names the backup. `packages/integrations/src/install.ts:16-17`, `:661-664`.
- **Install is all-or-nothing:** every target file is snapshotted, the writes land one file at a time, and the receipt is written last, so a receipt on disk always describes files that exist; any throw restores every snapshot and removes every backup, leaving a failed install indistinguishable from one that never ran. `packages/integrations/src/install.ts:19-22`.
- **A plan is pure:** each artifact carries `apply`, `strip`, and `ownedNow` as total functions of the file's current text, and nothing in a plan touches disk, so `--dry-run` is the real install's code path minus its last step and reports byte for byte what a real one would write. `packages/integrations/src/install.ts:7-12`.
- **The install order is the contract:** validate the root, refuse a symlinked path, re-hash the receipt, refuse an artifact we don't own, and only then snapshot, write, and record. `packages/integrations/src/install.ts:666-678`.
- **Uninstall has no `--force`:** the receipt is the only license to delete, every entry is re-hashed first, and one drifted entry refuses the whole uninstall, because overwriting an edit is recoverable from a backup and deleting a file somebody has made their own isn't. `packages/integrations/src/uninstall.ts:1-7`.
- **Nothing is inferred from a config file:** an MCP entry or a hook that resembles ours but that no receipt names is left alone; only an entry we wrote licenses a delete. `packages/integrations/src/uninstall.ts:9-11`.
- **Uninstall removes only its own directories:** `skills/memhtml` and `.memhtml-integrations` go when empty; `~/.claude` and `~/.cursor` are the host's, and an empty one stays because the host created it and may be about to write to it. `packages/integrations/src/uninstall.ts:43-50`.
- **`IntegrationModified` names the difference, never the contents:** it carries `host`, `path`, and a `detail` that's a hash, a missing entry, or an unmanaged sibling entry. Install refuses on it without `--force` and uninstall refuses always. `packages/integrations/src/errors.ts:3-15`.
- **Install with no host wires every host whose home directory exists:** `~/.claude`, `~/.codex`, `~/.cursor`, `~/.config/opencode`, each a directory the host creates itself on first run and never as a side effect of something else. `packages/integrations/src/hosts.ts:116-127`.
- **Transcript indexing hooks are Claude Code only:** `@memhtml/traces` reads Claude Code's JSONL format and no other, so a host with a `null` trace root installs no indexing hook rather than one with nothing to read; `MEMHTML_TRACE_ROOT` lets an operator who knows better say so for any host. `packages/integrations/src/hosts.ts:129-141`.
- **Claude Code project scope follows `AGENTS.md`:** a repository that already has one gets the instruction block there plus an `@AGENTS.md` import in `CLAUDE.md`, one copy of the prose visible to both, and the transaction layer decides by looking at disk because which file exists isn't a property of the host. `packages/integrations/src/hosts.ts:74-78`.
- **The binary triple is resolved once and recorded:** the node executable, the `memhtml` entry script, the `memhtml-mcp` entry script, and the version, because every command line in every host's config is derived from it, and `integrations doctor` comparing what resolves today against the receipt is what tells an upgrade from a move. The resolver refuses a build that produced one bin and not the other. `packages/integrations/src/locate.ts:1-13`, `packages/integrations/src/types.ts:45-54`.
- **Absolute binary paths by default:** an installed config records `process.execPath` plus the resolved entry script, because GUI hosts don't inherit a shell PATH and a moved toolchain alias has orphaned a bare command before; `--bare-command` writes `memhtml` and `memhtml-mcp` and leaves PATH to the operator. `packages/integrations/src/types.ts:40-44`, `apps/cli/src/commands.ts:1070-1075`.
- **Doctor reads, never scaffolds:** the store-root row reads the directory for `.memhtml/` and never calls `memhtml status`, because `status` on a bare directory scaffolds a store and a diagnostic that creates what it checks always passes. `packages/integrations/src/doctor.ts:10-12`.
- **Codex hook trust is informational with `ok: true`:** trust is keyed to a hook's hash inside the host and nothing outside it can read the decision, so a red row for something unknowable would train an operator to ignore the report. `packages/integrations/src/doctor.ts:12-15`.
- **Every path install writes is checked for symlink components:** the walk stops at the first component that doesn't exist, and an existing component that's a symlink refuses, because an installer must never follow a link into a place it didn't intend to write; a `~/.claude` linked into a dotfiles repo would turn a config edit into a commit in someone else's tree. `packages/integrations/src/fs.ts:155-163`, `packages/integrations/src/install.ts:678`.
- **`integrations shell --write` is the one symlink exception:** a `~/.zshrc` symlinked into a dotfiles repository is the normal setup rather than the hazard, and the operator named that file instead of it being derived from a host's config. `apps/cli/src/integrations.ts:460-470`.
- **`--project` resolves to the git top level:** the host files a project install writes are read from the root, so the path given is resolved with `git rev-parse --show-toplevel`, and not-a-repository, the filesystem root, and `$HOME` are each refused with `ERR_INVALID_FLAG` at exit 2, because what is unusable is the value on the command line. `apps/cli/src/integrations.ts:162-193`.
- **Each host is its own transaction, planned first:** with several hosts a refusal on the third would leave the first two wired, so every host is planned in dry-run form before any real pass, which turns partly applied into nothing written; what remains is a disk failure during the real pass, and the report names the hosts that did land. `apps/cli/src/integrations.ts:297-304`.
- **The rc-file PATH line is guarded:** the shell snippet wraps its PATH export in a `case` on `:$PATH:` rather than appending unconditionally, because an rc file is sourced once per shell and a nested shell would otherwise accumulate the same directory over and over. `packages/integrations/src/shell.ts:26-30`.
- **The recall discipline is stated once:** five paragraphs in `@memhtml/contracts`, recall, read, cite, reinforce, write, in the order an agent meets them; the guide topic, the instruction block, the skill, and the retrieval tool descriptions render that one list. `packages/contracts/src/guidance.ts:17-45`.

### The `memhtml hook` engine

`memhtml hook <event> --host <host>` is what an installed host hook runs. The engine lives in `apps/cli` and calls the dialect renderers from `@memhtml/integrations` to speak each host's protocol; the engine produces text and knows nothing about JSON envelopes or which host reads which stream (`packages/integrations/src/index.ts:4-6`, `apps/cli/src/hook.ts:35-38`).

- **It never fails:** a hook runs inside a host's turn, so a failure here would be a failure of the developer's session rather than of `memhtml`; every path funnels through `runHook`, whose error channel is `never`, and a storage failure, a defect, a missing plane, and a blown deadline all become the empty string at exit 0, which every host reads as "nothing to add". There's deliberately no way to tell those apart from a quiet store, because a hook has no channel in which to report one. `apps/cli/src/hook.ts:24-28`, `:323-333`.
- **It's bounded, and the bound is on the turn:** a recall event gets 1500 ms and an indexing event 10 000 ms, applied to the whole engine rather than to one query; expiry answers the empty string, so a slow store degrades to no injection rather than to a slow session. The indexing bound is longer because nothing waits on it, and still finite because a host that kills the process would lose the whole scan. `apps/cli/src/hook.ts:30-33`, `:79-87`.
- **Two events index, two inject:** `pre-compact` and `session-end` index transcripts and produce no output, ever; `user-prompt-submit` searches on the prompt and injects the hits; `session-start` recalls on the working directory and appends the open task queue. `apps/cli/src/hook.ts:70-71`, `:225-252`.
- **Defaults 5 hits and 3000 characters:** `--limit` defaults to 5 hits on a per-prompt recall and `--budget` to a 3000-character session-start pack, and `commands.ts` states the same values as the flags' documented defaults. `apps/cli/src/hook.ts:73-77`.
- **A gist is cut to 240 characters and a pack lists at most 5 open tasks:** the cut is so one memory can never dominate an injected block, and open work means `todo` and `doing`. `apps/cli/src/hook.ts:89-96`.
- **The dialect is asked first:** whether this host reads anything on this event is answered by `renderHookOutput` returning the empty string on a probe, before the store is touched, so a host that can't inject spends no part of the turn on a query whose result it would discard. `apps/cli/src/hook.ts:219-223`.
- **A hook never scaffolds a store:** building the app layer on a missing root would create a memory repo that nothing else ever reads, so `.git` is probed at the root, a file for a worktree as well as a directory, and a missing store prints nothing at exit 0. `apps/cli/src/hook.ts:335-356`.
- **The open-task list is a separate indexed scan:** `SearchScope` excludes `task` from every unscoped query, so the working set arrives through the direct scan that exists for it, in two calls because `ListTasksParams.status` is scalar and open work is two statuses; a failing task scan leaves the memory pack intact and the tail absent. `apps/cli/src/hook.ts:234-252`.
- **The per-prompt header states three rules:** the hits are the ranker's guess and never a citation, `memory_read` is how a body is obtained, and `memory_reinforce` is how the guess becomes evidence, because salience only moves on a read or an outcome and a block that didn't ask for those two calls would inject memories that can never learn from having been useful. `apps/cli/src/hook.ts:98-106`.
- **`hook.output` is the second envelope exception:** its success stdout is the host's hook protocol rather than the JSON envelope, as `help` on a terminal already is; its usage errors stay in the failure envelope, so the type still names the command in the manifest. `apps/cli/src/envelope.ts:51-59`.
- **Three error codes for the family:** `ERR_UNKNOWN_HOST` and `ERR_UNKNOWN_HOOK_EVENT` are usage errors at exit 2, since the fix is on the command line; `ERR_INTEGRATION_MODIFIED` is a runtime refusal at exit 1, a receipt-owned file or entry that doesn't match its receipt. All three are appended at the end of the list, because the list is append-only. `apps/cli/src/envelope.ts:137-144`.
- **Closed vocabularies arriving as positionals are refused before the app layer:** the hook event and the integrations host are checked in `run.ts` rather than in a dispatch arm, at exit 2 with the whole vocabulary enumerated as suggestions, because a refusal raised inside `dispatch` becomes exit 1 after a database was opened for a call that was never going to run; `memhtml hook nope --host claude` answers on a machine with no store. A closed-vocabulary flag needs no entry here, since `--host` declares its values and the flag check already refuses `--host nope`. `apps/cli/src/run.ts:1320-1361`.
