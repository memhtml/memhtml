# memhtml-public · Tech debt

Describes the source at 0.16.0 (2026-10-18). Citations are `path:line` into that tree.

This register was assembled from four channels, in this order.

First, a comment-marker scan. The repo doesn't record debt in code comments, and the scan re-run for this pass finds four hits, none of them a debt marker on this code (see **Explicit markers** below). Debt lives in ranked prose ledgers instead. `docs/backlog.md:3` states the rule for one of them, "Ranked. Each item names its evidence; nothing here is speculative," and the opening paragraph of `ROADMAP.md` names `docs/backlog.md` as "the fine-grained ledger" and itself as "the system-level view."

Second, those ledgers and a source review. `docs/backlog.md`, `ROADMAP.md`, and the EARS requirements in `spec/memhtml.symspec.json` each carry deferred items that name their own unfired trigger. Every ledger item that became a row was re-checked against source first. The v2 rows come from reading the session, head, snapshot, and curator packages and the head server for this release, and the two failures rows 2 and 3 describe were reproduced on a scratch store.

Third, manifest version pins. These cover the Effect catalog, the `effect/ai` module the MCP door imports, and the places where a declared schema version disagrees with the pinned one. One finding here is a watch item without a defect to rank. The exact pin `jsonc-parser` `3.3.1` is declared twice at the same version (`packages/integrations/package.json:35` and `tests-integration/package.json:33`). That's the shape row 27 flags, with its numbers still in agreement, and moving the pin into the catalog closes it for good. Eighteen manifests declare `effect` as `catalog:`, which is the blast radius of row 18.

Fourth, pattern-level smells the reviewer chose to flag. These are duplicated agent-facing prose across the two doors, one tool answered by two rankers that describe themselves as one, ledgers that outlive their defects, and an assist that reaches callers unevenly.

Citations into `docs/`, `apps/`, `packages/`, `spec/`, `tests-integration/`, and `.github/` were checked by a script against this tree. Citations into root files (`CLAUDE.md`, `biome.json`, `package.json`, `mise.toml`, `lefthook.yml`, `pnpm-workspace.yaml`) were checked by hand. `ROADMAP.md` is cited by section, because its line numbers move with every release note.

Category vocabulary is closed to eight values: `marker`, `wrong abstraction`, `error handling`, `dead code adjacent`, `deprecated pattern`, `version pin`, `duplicated logic`, `missing tests`. Cost is `S`, `M`, or `L`. Rank weighs cost to fix against the consequence of leaving it, so a cheap fix with a real consequence outranks an expensive fix with a contained one.

A row leaves the register only by being closed in code, and it leaves through the **Closed** section below. That's the discipline `docs/backlog.md` keeps with its struck `DONE (verified <date>)` headings. It guards against the failure mode this register's own smell section names, a ledger that outlives its defect, and against its mirror, a fix with no record that the ledger ever claimed otherwise.

Two limits apply to what follows. Every item is either a deferred capability the maintainers already argued for in writing, or a smell this review found, and nothing was invented to reach a row count. The register also describes only this repository, the software that manages a separate memhtml root located by `$MEMHTML_ROOT`. No memory lives here. Where an item's consequence lands on the root, the row says so.

## Pattern-level smells

### One workflow, two hand-written copies, one per agent door

The two surfaces an agent calls, the `memhtml` CLI and the MCP stdio server, publish the same authoring and batching rules as two independently written prose strings. Both tell the caller to supply exactly one of `body` or `article_html`. Both state that the markup must carry exactly one `<mark>` inside the first `<p>` or `<li>`. Both explain that the first `<time datetime>` element becomes the memory's event time, which is what recency ranks by. Both describe a fenced code block becoming `<figure><pre><code data-lang>` and promoting to a `lang:` entity. Both state that a batch is atomic by default with a flag for best-effort, and that a dedupe isn't a failure. Neither string is derived from the other.

Inside the MCP package the risk is handled. `apps/mcp/src/tools.ts:197-199` says two hand-written versions of one workflow "drift the first time the semantics move", which is why `ARTICLE_HTML_CONTRACT` and `BATCH_GUIDANCE` are shared constants. That sharing stops at the package edge. A grep for either name under `packages/` returns nothing. The MCP suite pins its own literal copy of the batch text (`apps/mcp/tests/tools.test.ts:166-172`), so it catches the MCP description drifting and can't see the CLI. Two agents holding two different doors to the same root can work from two different contracts, and neither can tell.

The fix this section prescribes exists for a different body of prose. `packages/contracts/src/guidance.ts` holds the recall discipline, and `apps/cli/src/commands.ts:1976-1985` gives the same reasoning given here, that four hand-written copies of one discipline would drift. `packages/integrations/src/render/block.ts:59` and `packages/integrations/src/render/skill.ts:58` render the same paragraphs into the installed instruction block and `SKILL.md`. The authoring and batching prose is still written twice, at `apps/mcp/src/tools.ts:154-165` and `:212-219` against `apps/cli/src/commands.ts:1838-1864` and `:1917-1942`. Extending the module to cover it is a small job now that three surfaces read from it. Register row 16 is the other half of the story, since the MCP door is the one surface the module doesn't reach.

### One tool, two rankers that describe themselves as one

`memory_search` and `memory_recall` ask the head server first and fall back to the SQLite index. The two paths rank differently. The index fuses lexical, vector, recency, and salience arms and diversifies with MMR, and the head fuses BM25 and the vector arm and uses recency only to break exact ties. `routeFor` sends a call to the index for archived records, `as_of`, a quoted phrase, or a query with no BM25 term, and to the head otherwise. The answer has v1's shape exactly, so a caller can't tell the doors apart by fields, and the only trace of the route is the `arms` list.

Everything an agent reads describes the index. The `memory_search` description names four arms and diversification (register row 1). The unused short recall discipline says reinforcement teaches the salience arm (row 16). The head gate that guards `curate merge` measures the head's lexical arm alone (row 11), so the gate and the default search path agree with each other and disagree with the description. The consequence lands on agents. An agent that reinforces hits to improve its next search, as the description and the discipline invite, changes nothing the default route reads.

### An assist that only half the doors can use

Write-time conflict detection was the campaign's largest measured win, and it reaches callers unevenly. The v1 prose door has it, so `memory_write_batch` and `memhtml apply --detect-conflicts` return a per-op `conflict` naming the colliding path, batch index, and claim. Three gaps remain on the v1 side, each documented and each with a different cause. An `article_html` op reports nothing, because the claim lives inside the caller's markup and the ops layer never parses it. Retrieval reports nothing, so a `memory_search` hit whose slot holds two live claims looks like one uncontested fact even though `frame_key` sits indexed on `files`. And a root created before migration 0009 carries NULL `frame_key` until a rebuild, so the assist finds fewer conflicts there. All three fail toward under-reporting, which is why they were deferred.

The session door works differently. A session commit parses every put, markup included, and links a `contradicts` edge from the new record to each live record that shares its frame key, using frame keys the head computes from the tree. So the session door covers the markup case and the pre-0009 case, and reports the result as an edge in the commit. The writer doesn't see a per-op `conflict` before the commit lands. The cost of leaving the v1 gaps is that an agent's confidence in "no conflict reported" depends on which door it used and how old the root is, and nothing in the response says which situation it's in.

Shows up in:

- `docs/backlog.md:57`
- `docs/backlog.md:55`
- `docs/backlog.md:69`
- `apps/cli/src/operations.ts:540-553`
- `packages/session/src/commit.ts:180-210`

Cost: L for the `article_html` half on the v1 doors, because the assist has to move behind the store's own render, and a second parse would add a second place the gist rule can drift. M for the retrieval half, and S for making the pre-0009 degradation visible in the response.
