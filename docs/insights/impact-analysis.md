# memhtml-public · Impact analysis

Describes the source at memhtml 0.15.1 (main `4778735`, 2026-09-17). Citations are `path:line` into that tree. Ranking data was re-measured at that commit over 416 `.ts` files; the previous measurement was at `9ad7240` (2026-09-10) over 363.

If you change surface X, this file lists what else you have to think about.

**A surface is high-impact here when changing it forces edits in more than one workspace package.** The ranking metric is the number of distinct workspace packages that reach the surface in the import graph, with the raw count of importing files as the tie-break. Raw inbound-file count is not the metric, because a contract surface can have the widest blast radius without having the most importers. `packages/store/src/layout.ts` has 21 importing files and reaches six packages. `packages/sleep/src/env.ts` has 39 importers, and every one of them is inside `packages/sleep`. Fan-out inside one package is refactoring work in one directory. Fan-out across packages is a change that has to land in agreement across a build graph.

Three destinations on this list have a blast radius that reaches past the build graph. This repository stores no memory. It is the software that manages a separate directory called the memhtml root, located by `$MEMHTML_ROOT` (`apps/cli/src/config.ts:62-67,188-191`). Every root that already exists holds files written by whatever version of this software created them. A change to the memory file format (`packages/html`) or to the root's on-disk layout (`packages/store/src/layout.ts`) changes data this repository does not contain and cannot migrate in a commit. Those two carry a "reaches existing roots" note. The third destination is not the memhtml root. `packages/integrations` writes into a host's configuration directory, outside both this repository and the root: `$HOME` at user scope and the git top level at project scope (`packages/integrations/src/hosts.ts:155-160`). At user scope that means `~/.claude.json`, `~/.claude/settings.json`, `~/.claude/CLAUDE.md`, and the installed skill (`packages/integrations/src/hosts.ts:168-175`), and the matching files under `~/.codex`, `~/.cursor`, and `~/.config/opencode` (`packages/integrations/src/hosts.ts:196-260`). `apps/cli/src/integrations.ts:88` resolves the user-scope root to `homedir()`, and the receipt that records what was written lands outside the repository as well (`packages/integrations/src/receipt.ts:33-36`). That surface carries a "reaches installed hosts" note.

The primary consumer of every surface below is a coding agent rather than a person at a terminal. A change to the JSON envelope is therefore high-impact, because agents parse it and branch on it. A change to a closed vocabulary is high-impact because that vocabulary is published in the machine-readable manifest an agent reads before its first call.

Ranking data was measured at commit `4778735` (2026-09-17) by walking every `.ts` file under `packages`, `apps`, `tests-integration`, and `scripts`, 416 files in all. Relative specifiers were resolved by path, and `@memhtml/*` barrel imports were resolved through each package's `src/index.ts` re-export map. That method inflates one set of counts. `packages/domain/src/index.ts:7-17` is 11 `export * from` lines, so a barrel import of one domain symbol credits all 11 domain files. No domain file is therefore selected on count alone. `packages/integrations/src/index.ts:15-21` is a second all-`export *` barrel with the same inflation, so a barrel import of one integrations symbol credits all 7 target files.

`Touch on change` reads as follows. `yes` means the consumer must be edited when the surface changes shape. `likely` means the consumer needs review even without a signature change, usually because it restates the surface's content somewhere the type system cannot check. `no` means only a behavioral change reaches it.

### Blast-radius notes

- Each error class carries only summary detail. `StorageFailure` carries an operation name, and the driver's own message goes to `Effect.logError` at the adapter edge (`packages/contracts/src/errors.ts:3-8`). Adding a payload field that carries SQL text, git argv, or a memory body would let corpus content reach an agent's tool response. The CLI edge does not reconstruct what the class dropped (`apps/cli/src/errors.ts:90-122`). The contract is that the payload is safe to return.
- `GitFailure` lives in `@memhtml/store` because it carries a git subcommand name, and the CLI edge's docblock still calls it the one error class outside this file (`apps/cli/src/errors.ts:34-36`). That is no longer the whole picture. `codeFor` also maps five plain classes that live outside contracts: `EmbedModelMismatch`, `IndexStale`, and `RebuildNoEmbedRefused` from `packages/index/src/indexer.ts:159-199`, `DiscriminationFailed` from `packages/eval/src/run.ts:167` (`apps/cli/src/errors.ts:60-71`), and `IntegrationModified` from `packages/integrations/src/errors.ts:8-15`, mapped at `apps/cli/src/errors.ts:74-75`. Adding a ninth class here without adding its case to `codeFor` yields `ERR_UNKNOWN`, because the switch has a `default` (`apps/cli/src/errors.ts:76-77`). Nothing in the type system catches that omission.
- `packages/domain` names `InvalidMemory` as a type only, and `packages/domain/tests/layering.test.ts` reads the emitted `dist/` to check that domain's runtime imports stay limited to `effect` (`packages/domain/src/index.ts:1-6`, `packages/domain/tests/layering.test.ts:7-12`). Converting that type-only import into a value import fails that test, so it costs more than adding a dependency.

### Blast-radius notes

- Every closed vocabulary in this file is restated at least once in SQL, and `MEMORY_TYPES` and `PARA_BUCKETS` are restated twice (`packages/index/migrations/0001_files.sql:18-20,34` and `packages/index/migrations/0008_tasks.sql:38-40,46`). - `arc` is in `MEMORY_TYPES` and absent from `WRITABLE_MEMORY_TYPES` by design. Tasks are excluded from search and skipped by sleep through filters that read this one column. Introducing a second axis would mean finding and changing every one of those filters.

### Blast-radius notes

- The class is derived from the rel instead of stored beside it. `relClassFor` is total over `ALL_RELS` and injective per class (`packages/contracts/src/edges.ts:65-75`), so a new rel added to one of the four arrays gets a class automatically. A new rel added without a matching SQL CHECK edit is refused by the driver at index time, because `packages/index/migrations/0004_edges.sql:30-34` and `packages/index/migrations/0008_tasks.sql:194-199` enumerate the rels per class independently.
- The class separation affects ranking. Every memory-graph query filters `edge_class = 'memory'`, so a person or task edge cannot enter PageRank, MMR, or the retention bridge count (`packages/contracts/src/edges.ts:3-8`). Promoting a task rel into the memory class would let an agent's to-do list reweight the retention of its knowledge (`packages/contracts/src/edges.ts:48-52`).
- `relTokenFor` and `relForToken` are inverses on the token image. The mapping replaces underscores with hyphens because a `rel` token cannot hold a colon (`packages/contracts/src/edges.ts:101-120`). `relForToken` converts every hyphen back to an underscore, so adding a rel whose name contains a hyphen breaks the inverse with no error.

### Blast-radius notes

- `archivePathFor` and `originalPathFor` are a matched pair. Archiving mirrors the whole original path beneath `archive/<YYYY>/`, which makes the mapping injective and invertible. `git log --follow` therefore reads through an eviction, and `diff -M` reports it as `R100` instead of a delete plus an add (`packages/contracts/src/paths.ts:205-214`). `originalPathFor` strips exactly one prefix, so it stays a left inverse even for a memory archived twice (`packages/contracts/src/paths.ts:216-225`). Changing either side without the other breaks archive-path round-tripping on every root that already holds archived files, with no error at the time of the change.
- `placementFor` is total. It always returns a directory rooted in a PARA bucket, so the write path never guesses twice and never fails (`packages/contracts/src/paths.ts:145-183`). An unusable explicit `path` is ignored instead of propagated. A caller that wants a bad path refused has to gate on `isValidMemoryPath` first, because `placementFor` rejects nothing.
- The `tasks` segment name is part of the contract, not a layout preference. Keeping tasks in one named segment is what makes `ls projects/<slug>/tasks` the list operation (`packages/contracts/src/paths.ts:21-30`). Renaming it orphans every task file in every existing root, because nothing migrates them.

An agent branches on `code` and not on the `error` prose, which changes freely as wording improves. Removing or repurposing a value breaks every already-deployed agent, and no test in this repository can detect that.
- The exit codes are a second, independent contract, kept stable so a shell caller can branch without parsing output: 0 success, 2 usage error, 1 runtime failure (`apps/cli/src/envelope.ts:119-122`, `AGENTS.md:24-25`). The two failure codes call for different fixes. Exit 2 is fixed by changing the call, and exit 1 by changing the repo or the environment. That guidance is authored once in `apps/cli/src/commands.ts:1352-1354` and rendered into the first-call block at `AGENTS.md:37`.
- `--dense` output is produced by `stripNulls`, which drops every null and undefined field recursively (`apps/cli/src/envelope.ts:172-186`). A consumer that distinguishes "field absent" from "field null" reads two different shapes depending on the flag. Adding a field whose null carries meaning breaks dense mode for that field, with no error to signal it.
- The one-envelope rule has two documented exceptions, and the file records the second one at the declaration. `help` on a terminal prints prose, and `hook.output`'s success stdout is a host's hook protocol rather than this envelope; its usage errors still use the failure envelope, which is why the type is declared at all (`apps/cli/src/envelope.ts:49-53`). `apps/cli/src/hook.ts:37` says the same from the other side: that module produces text and knows nothing about JSON envelopes. An envelope on that stream would be pasted into a host's context window as if it were a memory, so a change that routes hook output through `render` is a regression, not a consistency fix.

## Other notable surfaces

- `apps/cli/src/api-layer.ts:601-632`: the one composition root. `layerApp` is the single graph production runs, and `memhtml serve mcp` runs the same one in a child process, so an MCP tool and its CLI twin cannot look at different databases. 24 importers across 3 packages, but they consume tags instead of shapes, so most changes are contained.
- `apps/cli/src/commands.ts:179,1335,1551`: `COMMANDS`, `GUIDE`, and `buildManifest`. The manifest is derived by walking `COMMANDS` and `GLOBAL_FLAGS`, and `AGENTS.md` is generated from the same arrays (`AGENTS.md:1`), so `memhtml agents-doc --check` fails on drift (`apps/cli/src/agents-doc.ts:14-16,236-241`). Adding a flag updates both surfaces automatically. Adding a command without a `responseTypes` entry does not. `AGENTS.md` gained 82 generated lines between the two measurements, all of them derived from these arrays: the `memhtml integrations` and `memhtml hook` entries (`AGENTS.md:540-545`) and the three new error codes (`AGENTS.md:567-569`). Every `AGENTS.md` citation below its line 70 moved with them.
- `packages/html/src/parse.ts:385,417`: `parseMemory` and `checkMemory`, the format gate. Ten production call sites across six files: `packages/store/src/store.ts:618,664,1026`, `packages/index/src/indexer.ts:306`, `apps/cli/src/doctor.ts:502`, `apps/mcp/src/resources.ts:348`, `packages/sleep/src/tasks.ts:637,675,745`, and `packages/sleep/src/phases/entity-resolution.ts:605`. The store renders and refuses before it writes, so a format violation leaves the tree byte-identical.
- `packages/html/src/constraints.ts:358`: `checkDocument`, the six format constraints. It has only two production call sites, both inside `parse.ts`, so its blast radius travels through `parseMemory` instead of through imports. Constraints 1 to 5 are violations and constraint 6 is a warning, because the format has to degrade gracefully on a hand-written file (`packages/html/src/constraints.ts:28-36`).
- `packages/index/src/schema-const.ts:49,61,64`: `MEMORY_TABLES`, `TRACE_TABLES`, `STATE_TABLES`, and the size bounds (`packages/index/src/schema-const.ts:70,77,87`). 28 importers across 5 packages. The lists are stated once so a table rename is a compile error at every reader, and because a truncate list that has drifted from the schema leaves rows behind, which makes a rebuild incomplete (`packages/index/src/schema-const.ts:1-5`).
- `packages/store/src/store.ts:1308`: `linkMemories` and the write path. 10 importers, but only 3 packages. Four `apps/cli` files consume it: `apps/cli/src/api-layer.ts:49` (`Store`, `StoreShape`, `makeStore`), `apps/cli/src/operations.ts:43` (`Store`, `WriteInput`), `apps/cli/src/config.ts:13` (`expandRoot`), and `apps/cli/src/hook.ts:13` (`expandRoot`, the importer added since the last measurement). Only the first two touch the write path; the other two borrow a path helper.
- `packages/sleep/src/env.ts` and `packages/sleep/src/sql.ts`: 39 and 37 importers. By raw importer count, excluding barrel `index.ts` files, `packages/contracts/src/errors.ts` leads at 61, `packages/index/src/database.ts` is second at 40, `env.ts` is third at 39, and `sql.ts` ties `packages/domain/src/cosine.ts` and `packages/domain/src/ranking.ts` at 37. The tie between `env.ts` and `database.ts` that held at the previous measurement is gone. They are excluded from the main set because `env.ts` is imported only from inside `packages/sleep`, and `sql.ts` only from `packages/sleep` plus three `apps/cli` files.
- `packages/html/src/vocabulary.ts:53`: `META_ORDER` and the closed element vocabulary. 12 importers, all inside `packages/html`. The vocabulary itself is the policy, so there is no sanitizer library and no allow/deny logic (`packages/html/src/vocabulary.ts:1-6`). A stable meta order is what makes a meta-only edit a one-line git diff.
- `packages/domain/src/*`: 11 files at 30 to 37 apparent inbound references each, `cosine.ts` and `ranking.ts` at the top. That count comes from the 11 `export *` lines in `packages/domain/src/index.ts:7-17`, and the real per-symbol fan-out is much narrower, with the `MergeStage` restatement in the next bullet as the one counterexample that crosses packages. `packages/domain/tests/layering.test.ts` reads the emitted `dist/` to check that domain's runtime imports stay limited to `effect`, so any new value import here fails a test instead of adding coupling nobody notices.
- `packages/domain/src/merge.ts:198,228`: `MergeVetoReason` and `MergeStage`, restated as string unions in two more packages. `packages/eval/src/write-path-acceptance.ts:39-47` declares `AcceptanceStage` with its own spelling of the stages and veto reasons while importing the real functions beside it (`packages/eval/src/write-path-acceptance.ts:1-2`), and `packages/sleep/src/phases/dedup-merge.ts:602-603,643` holds a third copy of the stage names in its reporting. A renamed stage compiles in `packages/domain` and changes the eval and sleep counts silently, so this is a `likely` row spanning three packages that the domain bullet's count does not reach.
- `packages/integrations/src/doctor.ts:1-16`: the integrations doctor, a consumer that re-reads host wiring from disk and re-derives command lines rather than trusting the receipt. Every row is a fact read from disk or a child process, and the store-root row looks for `.memhtml/` instead of calling `memhtml status`, because a diagnostic that creates what it checks always passes. It imports the JSON reader, `cliCommand` and `mcpCommand`, `hostSpec`, the receipt comparators, and `claudeOwned` (`packages/integrations/src/doctor.ts:23-30`), so a change to the command-line shape, the host registry, or the receipt format reaches it. Its sibling `packages/integrations/src/locate.ts:1-12` resolves the `memhtml-mcp` entry once per install, and its `MCP_CANDIDATES` (`packages/integrations/src/locate.ts:30`) duplicates the two-candidate sibling-path walk in `apps/cli/src/serve.ts:54,61-62`: two copies of one deployment fact with nothing checking their agreement.
