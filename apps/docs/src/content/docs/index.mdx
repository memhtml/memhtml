## Status of This Memo

This document is the reference documentation for the `memhtml` implementation. It is not an Internet
Standard of any kind, and the form it takes is a claim about how the material is organised rather than
about where it came from: every architectural statement here names the file and line that implements
it, every measurement carries the date it was taken, and all fifty-seven pages of the Reference tier
are generated from the binary's own registries instead of written beside them. Where this site and the
binary disagree, the binary is right and a test is missing.

Distribution of this document is unlimited.

## Abstract

`memhtml` stores an agent's long-term memory as a git repository of semantic HTML5 files — one fact
per file — and treats that tree as the system of record. The SQLite index over it is a projection:
delete it and the cost is the time to rebuild, not a memory. Retrieval fuses four independently ranked
arms with reciprocal rank fusion, and a fifteen-phase nightly pipeline curates the corpus on a branch,
one commit per change, so a night of consolidation is a diff a person can read. Nothing is ever
deleted — eviction is a `git mv` into an archive that mirrors the original path, so `git log --follow`
reads straight through a memory's whole life.

## Conventions Used in This Document

The key words <span class="rfc-keyword">MUST</span>, <span class="rfc-keyword">MUST NOT</span>,
<span class="rfc-keyword">SHOULD</span> and <span class="rfc-keyword">MAY</span> are to be read as in
BCP 14 wherever they appear in upper case: they mark a requirement of the implementation, never an
emphasis. They are authored in capitals, not lowered into small caps by the stylesheet, so the
Markdown this page serves to an agent carries the same normative force the page shows a reader.

Sections are numbered in the heading text itself — `## 3.2. Edge encoding` — so that the page, the
table of contents, the search index, and the Markdown this site serves to agents all agree on which
section §3.2 is. Anchors stay unnumbered, so inserting a section does not churn an inbound link.

Architectural claims cite the code in repo-relative `path:line` form. Line numbers point into the
commit the site was built from and are not permanent addresses.

Every page on this site also serves its own Markdown source at the same path with a `.md` suffix, and
`llms.txt` at the site root indexes the whole corpus for an agent that would rather read the document
than the page. `memhtml manifest` answers with every command, flag, response type, error code and
environment variable the binary accepts, on a machine with no repository, no database and no
credentials.
